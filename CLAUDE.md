**Undo model.** Clip + automation edits push `ClipSnapshotAction`/`AutomationSnapshotAction` immediately. Mixer ops (fader/pan/mute/solo/rename/recolour/routing) have NO per-gesture wiring — `MainComponentEdit.cpp::pollMixerUndo()` (from the 10 Hz timer) compares an allocation-free mixer **fingerprint** and records ONE `MixerSnapshotAction` once a change settles (~300 ms); the JSON snapshot is built only when a baseline is taken or a step committed, and a take only marks the baseline stale. Initial `MixerSnapshotAction::perform` captures the already-applied gesture without calling `applyAll`; real undo/redo still replays state. Keep the zero-redundant-reload regression.

**One timeline span for the whole EDIT view (2026-08-12).** `Source/UI/EditTimeline.h` holds `kNotionalEmptyLaneSec` / `notionalEmptyLaneSamples(sr)` — the span a lane and the ruler cover when the session has **no audio yet** (5 notional minutes, at the DEVICE rate). Session ▸ Session Settings is `SessionSettingsDialog` (own file; reaches the host through callbacks). The WRITE tier (`canRepatch`, `canCaptureGains`) can wreck a show. **`ConsoleLink::canWrite()` gates every write on `profile.dialectTrusted || dialectConfirmed`.** `dialectTrusted` is a claim about the ADDRESS MODEL (documented + pinned by tests — true only for X32/M32); `dialectConfirmed` is set when the console answers the connect-time probe. So a dialect written from published docs with no hardware to test on is safe to ship: it degrades to read-only, never to writing a guess. **Never set `dialectTrusted = true` for a dialect you haven't pinned with encode/parse tests**, and never claim a capability whose encoder is null — `ConsoleTransportTests` fails the build on both. Don't fake repatch for a desk we can't talk to; see the 2026-06-10 and 2026-08-13 ADRs in `decisions.md`. The menu bar is `File · Edit · Track · Session · Help` (Edit = timeline/audio; Track = channel management). **Session replacement and long file operations (2026-08-18).** New/Open/CSV/Console/template/Finder paths call `confirmSessionReplacement` before replacing an active session; save failure cancels the transition. ## Implementation invariants

### Core (September baseline, October audit updates)

- RECORD runs in stages (`MainComponent::onRecordClicked`): `handleRecordPressDuringTake` consumes a press during a take; `prepareRecordStart` runs **every** refusal (no tracks/device/inputs/arms, StereoMix sources, clock mismatch, disk space) before anything changes; only then `applyRecordAutoRouting` and exactly one of `startDaemonTake` / `startSelectionPunch` / `startLocalTake`. Never add a side effect to `prepareRecordStart`.
- `isRecording()` includes daemon capture. Arm changes are refused while rolling; the recorder freezes `captureArms` for both capture and FIFO gates. Never rely solely on current UI arm state.
- `reorderTracks` is the shared media/state transaction for moves and deletion. It preserves complete stereo blocks, archives removed audio, remaps UUIDs/cues/automation/sends and clears stale undo/clipboard state. Do not reintroduce ad-hoc swap renames or manual per-index key shifts.
- It is also expensive (stops the player, detaches the audio callback, renames every take file, rewrites session documents — all on the message thread), so **one user gesture = one `reorderTracks` call**. Build the complete order with `Source/Audio/TrackOrder.h` (`logicalBlocks` / `moveBlock` / `flatten`; a stereo pair is one block) and commit it once — the EDIT swatch drag previews via `EditPage::updateReorderPreview` and commits in `mouseUp` via `commitReorder`. Never call it per pointer step. `MainComponent`'s `onTracksReordered` handler is the single place that rebuilds strips, refreshes EDIT rows (asynchronously — it can run inside a row's own `mouseUp`) and rescans waveforms after any reorder. `EditPage::refresh()` rebuilds on a changed logical **layout** (`TrackList::matchesLayout`), not just changed counts.
- Keep `Session File Backups/reorder_*` journals and metadata available for recovery. `Removed Tracks/<uuid>` contains retained audio, not disposable cache. Ordinary backup snapshots contain metadata only; these transaction folders have different retention semantics.
- Playlists distinguish initialized-empty from absent. Preserve them across same-session imports/reloads. Persist source channel and session-relative media path (`sessionAudioFile`, legacy `audioFile` fallback); missing explicit media stays silent.
- Persist strip UUIDs in `session_mix.json`; commit settings UUID changes after other property writers have reloaded. Index-based automation must be remapped explicitly, not assumed UUID-based.
- The installed `443c769` build uses protocol 4: require a compatible Hello and mutual HMAC-SHA256 authentication before delivering commands, then configure device/rate/routing/arms/pre-roll/redundancy before Start. Both Macs and the current distribution package have the matching `443c769` protocol-4 pair. Keep GUI/helper upgrades paired and do not silently adopt an old helper. STOP distinguishes command acceptance, capture completion and finalization health; never claim idle from a button click or kill a daemon from stale status. Package the matching daemon per INSTALL.md.
- A fresh take never replaces an existing `Track_NN` in any supported container. Existing media requires an explicit continue/punch path even when the session is unreadable. Check before opening any writer, not after.
- Backup/mirror copies count as active only after their directory and writers open. Latch start/runtime failures through stop, and group disk byte rates by physical volume when estimating remaining time.
- Long analysis/edit operations capture immutable state on the message thread, render on a background worker, and publish only if the session and source arrangement are unchanged. They refuse both local and external recording.
- Marker naming callbacks resolve runtime identity after sorting and asynchronous completion. Automation snapshot restore replaces rather than merges. Template-default IDs occupy 2000–2099.

**Engine and playback (2026-10-29 bug hunt)**
- **`inputRouting` is the REQUESTED patch and is what every save writes.** The wrap onto a smaller device (`i % numInputs`) happens only where routing is live: the callback, MIXER/EDIT/PATCH display, record-start checks and the daemon config (`TrackState::effectiveInputRouting`, `AudioEngine::getEffectiveInputRouting`). **Capture, punch and continuation**
- Manual punch: while playback rolls, RECORD punches at the live playhead even if an older EDIT cursor exists; when stopped, an explicitly placed cursor is used. A manual punch ends with one RECORD or STOP press; a normal live take keeps the two-press guard. Continuation at the end of a take is a separate part file, never a punch into the original.
- The punch writer adopts the existing take's container and bit depth on primary, backup and mirrors before stashing anything; mixed or unreadable existing media fails closed. Every copy needs a matching original before a punch, and all stashes complete before any writer opens. Originals stay as `.punchbase` until every spliced copy commits; surface rollback and save the session document/mix on stop.
- Never delete an existing `.punchbase` to start a new pass. Recover it before session playback/open, archive any partial replacement under `Session File Backups/Interrupted Punch*`, and refuse a new capture after a recovery until the restored take is reopened.
- Pre-roll applies to fresh takes only. Newly armed tracks in a punch/continue get a silent lead-in to keep timeline alignment. Selection punches capture only `[in, out)` in the audio callback, never from the UI timer; loop playback is suspended until teardown, and monitoring switches the armed track from old take to live input only during capture.

- **Punch and continue arms are exclusive and belong to one start.** Every refused start, in a recorder stage or an `AudioEngine::startRecording` guard, calls `discardTakeArms`, and every refusal sets `startError`.

## Critical universal rules

### std::sort comparators must be a STRICT WEAK ORDERING
- The hardened `std::sort` (newer Xcode/libc++) **aborts (SIGABRT)** when the comparator isn't a strict weak ordering — a real crash, not a warning. The classic trap: reversing a sort with `return forwards ? lt : ! lt;`. `! lt` reports *equal* elements as each `< ` the other (and `cmp(a,a) == true`), which is invalid. **Reverse by swapping the operands**, never by negating: build the comparison from `rows[forwards ? a : b]` vs `rows[forwards ? b : a]`. Also map non-finite floats (NaN) to a floor so the key is total. The sortable table dialogs (`SessionRecoveryDialog`, `QcReportDialog`, `NoiseReportDialog`) all follow this; copy that pattern in any new one. This crashed the app on relaunch-after-crash (the recovery dialog) — `SessionRecoverySortTests` guards it.

### Don't block the message thread (2026-08-11)

The message thread runs the 10 Hz timer that services punch, the transport labels, the meters and the menu state. Blocking it for seconds is indistinguishable from a hang to an engineer mid-show, so **unbounded file or subprocess work belongs on a thread**:

- **Owned + joined, never detached — and only through `sessionJobs`.** Every unbounded session-file job (track export, stem/mix bounce, import, Save As copy, relocation, show handoff, click render) runs on `MainComponent::sessionJobs` (`Source/UI/SessionJobRunner.h`): `reserve()` the session-I/O reservation, `release()` it on any pre-launch exit (chooser cancelled, validation failed), then `launch (work)`. The work runs on the owned thread with a cancel flag and **returns** its completion; the runner clears `sessionIoBusy` on the message thread *before* the completion runs, on every path — a cancelled job that returns `{}`, or one that throws. Never write a raw `std::thread` in `Source/UI` or release `sessionIoBusy` from a worker: eight hand-written launches each owned their own release, and the track export's cancel path skipped it, so a quit-cancel left every session operation refusing until restart. The destructor's `sessionJobs.cancelAndJoin()` keeps jobs from outliving the engine. Metadata saves share `sessionIoBusy` through their own `pendingMetadataSaves` count; `enqueueMetadataSnapshot` refuses while a job holds it, so the two owners never overlap. Gate: *session jobs release their reservation structurally*.
- **Resolve engine state on the message thread, then hand plain values to the worker.** `startExportTracksTo` builds its job list (source files, dest stems, stereo flags — all reads of TrackStates) up front, then the worker touches nothing but `juce::File`s; the stem bounce likewise resolves each stem's name/layout before launch. Report back through the returned completion with a `SafePointer`.
- **A UI worker never holds `recorder.getStructureLock()` across a render.** The 10 Hz timer calls `engine.captureStatus()`, which takes that lock, so a bounce that held it for the whole render froze the entire app until the last window was written. `forEachStereoMixWindow` snapshots every strip it reads (gain, pan, mute, VCA, bus flag, sends) under a brief lock of its own and renders lock-free; the file is the mix as it stood when the bounce began. Gate: *UI workers never hold the structure lock across a render*.
- **Timeline mutations go through `MainComponent::canMutateTimeline (action)`.** It refuses — with the reason on the status line — while capturing (local or daemon), while `sessionIoBusy`, and while LOCKed. Keys, menus and editor enablement gate these too, but every clip/range/marker/automation/undo function checks here instead of repeating a partial `isRecording()` guard (18 copies did, and none checked LOCK or session I/O).
- **`juce::ChildProcess::readAllProcessOutput()` has NO timeout** — it loops on a blocking pipe read until the child closes it. `waitForProcessToFinish(ms)` placed *after* it is dead code. Wait first (then `kill()` on timeout), and put the whole call on a background thread if the child can hang (`MultitrackRecorder::querySmartStatus` does both; `MainComponent::pollSmartStatusAsync` keeps one probe in flight).
- **Never write to the session volume while a take is rolling.** `preflight::measureWriteSpeedMBps` writes 16 MB; the pre-flight checklist now reports the requirement only when `isRecording()`.

### Real-time discipline (audio thread)

- The audio callback never allocates, locks, opens files, calls `Logger`, or touches the message thread.
- **`MultitrackRecorder::getTrack(i)` is NOT bounds-checked in release** (it's `*tracks[i]`, called once per strip per block). Every caller range-checks against `getNumTracks()` first; a debug `jassert` catches the ones that don't. **Never bound a loop that dereferences a TrackState on `player.getNumTracks()`** — the player's count comes from files on disk and can exceed the mixer's strip count (delete a strip after recording). That mismatch is what indexed off the end of the vector in the stereo-mix bounce; the mixer is authoritative for anything that reads mixer state. `jmax(recorder, player)` is fine purely as a *range check* on an index, which is how the other `AudioEngineClips` entry points use it.
- **The mix rules have ONE definition: `Source/Audio/MixKernel.h` (2026-10-29).** The solo / mute / VCA gate (`mix::audible`), the stereo-pair lane rule (`mix::automationChannel`), lane resolution (`mix::resolveLanes`), the post-fader mute (`mix::postFaderMuted`), send gain, the constant-power pan law and master gain are called by BOTH the audio callback and the offline stereo bounce. Never re-derive one inline: the invariants gate refuses a pan law, VCA-solo gate, stereo-pair ternary or send-gain formula in `AudioEngine.cpp` / `AudioEngineClips.cpp`, and AudioCallbackTests' "Live playback and the offline bounce mix the same session identically" compares the two outputs sample for sample (it found the live path reading lanes at the block END, one block late). Live reads lanes at the START of the block the player rendered (`playbackBlockStart`); the bounce at each 512-sample step's start, every strip under ONE blocking `automationLock`. Deliberate differences, not drift: the bounce has no live input, no trim-follow and no mono-master fold-down.
- **The audio callback reads automation ONCE per block (2026-10-29).** Right after `autoPlayPos`, it resolves every strip's lane-driven inputs into `resolvedMix` (`mix::StripLanes`: volume dB incl. lane trim, pan, Mute-lane state, and the monitor's mute rule) under ONE `ScopedTryLock` on `automationLock`, then every consumer -- `effectiveGainDb`, aux sends, `channelAudible`, the stream bus and the monitor sum -- reads that. Never call `automationValueAt` inside the callback again: it made up to six separate try-locks per strip per block, so a UI edit landing between them mixed one block from the curve on one path and the fader on another. SUSPEND or a stopped transport uses static values. Losing the lock while rolling HOLDS the previous block's lanes when they came from the same strips (same count and track generation); dropping to static values there un-muted Mute-lane strips for a block and clicked.
- **Offline renders must not use the RT automation read.** `automationValueAt` is try-lock + fall-back-to-static (correct: the audio thread must never block). A bounce that used it baked static fader values into the file wherever it lost the lock. Render paths take `automationLock` BLOCKING (the stereo bounce once per step via `resolveStripLanesLocked`; single reads via **`automationValueAtOffline`**); everything shares `automationValueAtLocked`.
- State transitions happen via `std::atomic` flags. Writers + readers are constructed / destroyed only on the message or background threads.
- Scratch buffers (`outputAccum`, `playerScratch`, companion ring) pre-allocate in `audioDeviceAboutToStart`.
- Master mute is enforced at the device boundary for the selected master output pair. Per-strip and stream routes are accumulated before the master bus and may share those channels; never implement mute by zeroing only the stereo master sum. Other direct/FOH outputs stay independent.
- **`TrackState` lifetime is shared (2026-10-29).** `MultitrackRecorder` owns tracks through `shared_ptr` and `TrackState` derives from `enable_shared_from_this`. Every UI surface that caches a `TrackState&` (`ChannelStrip`, `LedMeter`, `MiniSpectrum`) also holds `std::shared_ptr<TrackState> keepAlive`, taken in its constructor with `s.weak_from_this().lock()`, so a track the recorder drops -- `setStripCount` shrink, delete, session open/close, or a device restart that reshapes the set in `MultitrackRecorder::prepare()` -- stays valid until that surface is rebuilt. This closes the use-after-free class that four audits re-fixed one call site at a time; ASan reports it if a keep-alive is removed (*Strip lifetime* suite). The audio thread only dereferences the recorder's pointers and never copies one, so no reference-count traffic or deallocation happens there. Gate rule 1 requires the keep-alive on any new caching surface. **`condemnAllStrips()` is still called before frees** so detached surfaces stop their timers at once instead of showing a stale meter for a tick, and it must still reach all three views (gate rule 2), but correctness no longer depends on remembering it at every free. Any layout change bumps `getTrackGeneration()` -- add/remove, stereo link/unlink, and `reorderTracks` -- and both views rebuild on a generation change; `EditPage::refresh()` additionally compares the logical layout. Original rule, kept for history: **Any path that FREES `TrackState`s (shrinks the recorder vector) must call `condemnAllStrips()` FIRST.** A `ChannelStrip` holds a `TrackState&` and its meter/spectrum/strip timers keep sampling `state.peak/armed/...` on the 10 Hz clock until `rebuildStrips()` runs on the *next* tick — so `setStripCount` to a smaller count, `setStripCount(0)`, or `resetAllStripState()` under live strips opens a ~100 ms freed-heap read window. `condemnAllStrips()` stops every strip's timers (via `invalidate()`) before the free; it's idempotent and a no-op on an empty vector, and each caller sets `lastTrackCount = -1` to force the rebuild. **It covers BOTH views.** The EDIT rows have the identical hazard — each `EditPage::TrackRow` owns a `LedMeter` holding a `TrackState&` on its own timer, and the rows rebuild only on EditPage's next 24 Hz tick — so `condemnAllStrips()` also calls `editPage->condemnAllRows()` → `TrackRow::invalidate()`. Fixing this on the MIXER alone (three times) left EDIT reading freed memory the whole time; when you add a surface that caches a `TrackState&`, wire it into `condemnAllStrips()` in the same change. Callers that must condemn: bulk strip delete, session open (`openSessionFolder`)/close, console-session build, **and every "new/blank session" path** (`launchNewSessionDialog`, `applySessionTemplate`, `createSessionFromCsv`, `showStartupWelcome`). Growth-only `setStripCount` (import, AddTracks, click generate) frees nothing and needs no condemn. This UAF class was closed incrementally and kept leaving missed sites — grep every `setStripCount`/`resetAllStripState` caller when touching this.
- **Hero panels over the flat `bgDeep` body are `setOpaque(true)`** (`BigClockPanel`, `PerfDashboard`) — they `fillAll(bgDeep)` first so the look is unchanged. A non-opaque panel that repaints on a timer forces `MainComponent::paint` to redraw the slice behind it every tick; keep timer-driven panels opaque. Idle CPU itself is dominated by the CoreAudio device callback + the per-strip meter/UI-timer swarm, not these panels — see `decisions.md` *Idle CPU left at ~5%…*.
- **Live recording waveform** is built on the audio thread: `TrackState::liveWavePush` bins captured input into min/max pairs and pushes them through a pre-allocated lock-free `AbstractFifo` (`liveFifo`); the EDIT timer drains it (`liveWaveDrain`) and draws. Keep it allocation-free + lock-free on the push side — never grow the ring, log, or block there. Reset via `liveWaveReset()` on record start (message thread). This is why the live waveform is detailed + final-on-stop (no post-stop re-scan), like Reaper/Pro Tools.
  - **The live envelope OWNS the lane while capturing — even over clip blocks.** In `EditTrackRow::paint`, `showLive` (`liveRecording || liveHold`) takes precedence over `haveClipBlocks`: the continuous live path draws when `! haveClipBlocks || showLive`, and the static clip-block renderer is skipped while `showLive`. This is essential for a **continue** — every stop seeds a default clip over the take, so a continued take has `haveClipBlocks == true`; without the override the growing capture would be hidden behind the static clips until the post-stop re-scan. The existing take draws dim (`drawContinueExisting`, `[0, base)`), the new audio grows hot on top (`drawRecEnvelope`), then the clips take back over on stop. Don't gate the live envelope behind `! haveClipBlocks` alone.
  - **The live envelope is placed by TIMELINE FRACTION, not stretched to the lane.** `recPeakL` covers `[0, recPos]` (`recPos = recPeakL.size() * kLiveBinSamples`); the lane covers `[0, total] = max(playerTotal, recPos)`. `EditTrackRow::paint` confines `drawRecEnvelope` to `liveFrac = recPos/total` of the lane and draws the dim existing take across `existingFrac = playerTotal/total`. For a **continue** these collapse to the old behaviour (`liveFrac == 1`, take is the `[0, takeEnd)` prefix). For a **punch** `total` is the full take so `liveFrac < 1` and the capture sits AT the punch point (with the whole take dim under it) — **don't** draw the envelope across the full lane width or a punch looks like it records at the END. The silent prefill columns in `recPeakL` encode the offset within that confined slice.
  - **`EditTrackRow::paint` ALWAYS paints the pinned header last, in every lane VIEW mode.** The lane-content drawing runs inside a `drawLane` lambda so the non-waveform modes (Click / Tempo / Markers / Volume·Pan·Mute automation / comp lanes) can early-`return` from the *lambda* without skipping `paintHeader(...)` below. They used to `return` straight out of `paint()`, skipping the header — so when the timeline was scrolled the automation line/curve drew over the pinned name + I/O combos (the header is normally redrawn on top to cover lane content under the pinned-left region). Don't add a lane mode that returns from `paint()` directly; return from `drawLane` (or fall through) so the header still paints.
  - **The EDIT ruler MUST track the wave's horizontal scroll (2026-06-16).** `EditTimeRuler` is a FIXED-width sibling drawn ABOVE the wave lanes — it does **not** live inside the scrolling `viewport` — so it subtracts `viewport.getViewPositionX()` from its time→x map (`rulerTimeToX` − `scrollOffsetX`; the inverse `rulerXToTime` + it, so marker hit-test / shift-drag punch stay right). `EditPage` pushes the offset via `viewport.onScroll` (which `ScrollViewport::visibleAreaChanged` fires for manual **and** programmatic/auto-scroll + zoom-to-selection) and again in `resized()`. Omit it and every tick / label / playhead / edit-cursor / marker drifts right of the audio by exactly the scroll amount once zoomed in — the recurring **"ruler bug."** The ruler's `pxPerSec` maps across the full `contentW` (same as the lanes); only the origin shifts. Locked by `EditRulerScrollTests`: the ruler playhead must equal the lane's `headerW + (int)(frac*(waveW−8)) + 4 − scrollX`.
  - **Live-draw arming is SELF-DRIVEN per row, every tick — never a one-shot.** `TrackList::pushRecLevels` (EDIT timer) calls `row->setLiveRecording(true, prefill)` for each **armed** row every tick before draining, deriving the live state from the current recording+armed state (`setLiveRecording` only resets on the off→on edge, so it's idempotent). Do **not** re-introduce a one-shot "record just started" arm: if that single edge is missed or clobbered by a refresh between ticks, `appendLivePeak` early-returns on `! liveRecording` and silently discards every drained peak for the rest of the take (the live waveform never builds — this was the long-standing "continue doesn't show the waveform" bug). Arm **only armed rows** — a blanket arm of every row put non-armed lanes into an empty live state and blanked their existing waveforms. `prefill = recordBaseSamples / kLiveBinSamples` anchors the continue's new audio after the existing take. `LiveWaveContinueTests` locks the recorder-side data path (a continue emits live-overview columns like a fresh take).
- **A take is a SEQUENCE OF FILES.** `Track_NN.<ext>` + `Track_NN_partXX` continuations (auto-split past the container cap, or **continue-recording** via `armContinue` → `nextContinuationPart`) are stitched into one seamless take by `ConcatReader` (`Source/Audio/MultiPartReader.h`) on playback (`SessionPlayer`), the EDIT thumbnail (`thumbnail.setReader`), **and File ▸ Export / Bounce** (`TrackExporter` calls `ConcatReader::create` — an export used to silently contain only part 1). Any code that reads a whole take must stitch its parts; matching `Track_NN.<ext>` alone drops every continuation. **Continue/append never modifies an existing file** — it only adds a new finalised part, so it can't corrupt what's captured. Prefer this (a new part) over rewriting a file. The splice below is now only for a mid-take punch.
  - **Takes are not always WAV.** Session load (`SessionPlayer`), noise analysis, song detection, **the transient cache** (`buildTransientCacheInto` — Tab navigation was dead in FLAC/AIFF sessions until 2026-08-11) and **the timeline CSV** glob every supported container (`.wav/.flac/.aif/.aiff`), not just `.wav`. Filter by extension; parse the track index from the `Track_NN` **prefix**, not the last `_` (which turned `Track_04_part02` into `part02` → dropped). A `Track_NN*` glob also matches `Track_NN.punchbase.<ext>` — **explicitly skip `.punchbase`** (`takeIsMultiPart` and `swapTracks` both did not, despite comments claiming otherwise).
  - **A CONTINUE extends the take in ITS container, not the current capture format.** `startRecording`'s continue scan resolves the existing take's container + bit depth off disk and adopts it. Looking only for the *current* format's extension meant that changing format between takes found nothing: `recordBaseSamples` stayed 0 and the "continuation" was written as `Track_NN.flac` part 1 next to the existing `Track_NN.wav` — two files claiming one track index. Locked by *Continue-record adopts the existing take's container*.
  - **The recorder's failover keys on `WriterChannel::active`, NOT `writer != nullptr`.** A failed primary writer nulls `writer`, which is indistinguishable from a deliberately-empty stereo-R slot; keying the drain on `writer` skipped the whole channel (backup + mirrors + FIFO) after a primary failure. `active` is set when any destination opens at record start; a participating channel keeps draining even with a dead primary so backup/mirrors keep rolling. See the audit ADR in `decisions.md`.
- **STOP parks the transport at the take's END, not 0 (live-recorder convention).** `AudioEngine::stopRecording` **fails closed when not recording** (a stray OSC/console transport-stop while idle or playing back would otherwise run the whole tail — reload the last session, reseed clips, yank the playhead — and wipe edits). When recording, it captures `recorder.getRecordTimelineSamples()` **before** `recorder.stopRecording()` (which zeroes the recorder's base offset), then after `player.loadSession` — which rewinds to 0 — restores the playhead there with `player.setPositionSamples(...)`. This is deliberate and the opposite of a DAW (Reaper's Stop snaps the edit cursor back to the pass start): leaving the playhead at the end is what makes a subsequent RECORD take the **append-a-new-part** branch in `MainComponent::onRecordClicked` (`pos == total` ⇒ `continueAppend`), so continue resumes seamlessly. Don't "helpfully" rewind to 0 on stop — that reintroduces the "continue starts from the beginning" bug.
  - **Same-session reloads PRESERVE clip/comp edits; only a genuine session OPEN wipes them.** `seedDefaultClips(preserveEdits)` and `AudioEngine::loadSession(dir, preserveEdits=false)` are the knob: `stopRecording`, the click-track regen, and `swapTracks` pass `true` (keep every edited track's splits/fades/comps, reseed only plain defaults); the real open funnel passes `false` because its `.zfproj` playlist restore repopulates. `swapTracks` swaps the engine's clip lists + comp playlists for the two indices rather than reloading through the wiping path. This closed a data-loss blocker (record-stop / reorder / OSC-stop silently wiped all comps). Locked by *swapTracks preserves clip edits* in `RecordingIntegrityTests`. **`swapTracks` renames ALL of each take's on-disk files — the main `Track_NN.<ext>` AND its `_partXX` continuations, across every container (`.wav/.flac/.aif/.aiff`) — via collision-safe temp staging.** Renaming only `Track_NN.wav` (the old behaviour) stranded a continued or FLAC/AIFF take's parts at the old index, so a reorder permanently stitched them onto the wrong channel; locked by *swapTracks renames continuation parts*.
    - **The "edited" test (`isPlainDefault`) must NOT compare clip length to file length.** A continue-record / length-changing punch GROWS the file, so an unedited default clip left at the old length would be misclassified "edited" and preserved SHORT — silencing the appended audio (a real regression, caught by a re-audit and locked by *Continue-record grows the take* in `RecordingIntegrityTests`). A plain full-from-zero single clip (no split/fade/gain/mute/move/cross-track-file) is always refreshable to the current length; only those shape edits, or >1 clip / >1 take, count as "edited". A pure END-trim reloaded in place is refreshed back to full — audio is never lost, which is the correct trade for a recorder.
  - **Record-safety guards live at the ENGINE, not just the UI buttons.** `startPlayback` refuses while recording, `stopRecording` fails closed when not recording, `setTrackStereo` refuses while recording. Network/remote entry points (OSC, MCU, companion, timecode chase) reach the engine directly and bypassed the UI guards. Add new transport/layout entry points at the engine level or they'll be reachable from the network unguarded.
- **Punch-in is OFFLINE, never a real-time write into a take.** A punch records a clean fresh `Track_NN` from 0 like any take; the existing copies — **and all their continuation parts** — are moved to `.punchbase` sidecars in `startRecording` (before the writer truncates) and spliced back in `stopRecording` via `Source/Audio/PunchSplice.h` (`base[0,punchIn)+fresh+base[after]`, temp + atomic swap, all copies). The splice sits **after `closeWriters()` but before the async SHA thread** so the report's SHA/length describe the spliced files. Keep it there — never push punch writes onto the audio thread, and never overwrite a take in place (a failure must revert to the untouched base). **Multi-part bases ARE supported** (a take built up by continue-recording): `splicePunchParts` reads the whole take (all stashed part sidecars) via `ConcatReader` and **flattens** it into one spliced `Track_NN` (the parts are deleted on success, restored on failure). So you can punch anywhere on any take, single-file or split. `armPunchIn` sets `recordBaseSamples = punchInPos` so the clock / playhead / live-capture waveform anchor AT the punch point (the new audio builds there, existing take dim underneath) — same machinery as a continue. The punch point is the EDIT cursor (set by a wave-pane click, `EditTrackRow::mouseDown`) or the playhead. See the punch ADR + *Read-only offline DSP is allowed…* in `decisions.md`.

The original 12 are summarized here; `tools/invariants_audit.sh` defines the full current set: (1+2) every consumer of a cached `TrackState&` exposes a detach hook **and** is wired into `condemnAllStrips()`; (3) no `getTrack()` bounded by a player-derived count; (4) `TrackState::name` written only via `setNameThreadSafe`; (5) no `.wav`-only `Track_*` globs; (6) bare `Track_*` globs exclude `.punchbase` sidecars; (7) the sessions root resolved only via `AudioEngine::getSessionsRoot()`; (8) no bare `reload()` on the shared `.settings`; (9) offline renders read automation under a blocking lock; (10) **device reconfiguration is guarded against a live take**; (11) **`Theme/` paints accents via `brand::onSignal`, never a hardcoded `Colours::white`/`black`** (only `BrandColors.h`, home of `gloss()`/`onSignal()`, may name them); (12) **a `std::thread` join is never skipped by an early flag return** -- destroying a joinable thread calls `std::terminate()`, and a reader that clears its OWN run flag turns `if (! running.exchange(false)) return;` into a process abort (a Yamaha/A&H desk dropping its link killed the app on the next Connect or quit; the rule found two more sites written the same way the moment it existed). Rule 11 exists because the DESIGN gate **excludes `Theme/`** -- which is how `drawToggleButton` shipped a hardcoded white letter over every caller's accent: right for record red, ~1.2:1 on solo yellow. An exclusion added so a gate can express a rule becomes the one place the rule isn't enforced; a LookAndFeel paints for every call site, so it's the most expensive place in the codebase to hardcode a colour. **When you add a rule, verify it goes RED against an injected regression before landing it** — two of the original seven were blind (a commented-out call, and an unrelated comment in the same file, both satisfied the check); the rules strip comments (`sed 's,//.*,,'`) before grepping for exactly that reason. Every rule enumerates over the **consumers** of a hazardous pattern, not the call sites that trigger it — that's what makes it find instances reading missed. Rule 10 did so the day it landed: `setAudioDeviceSetup()` / `initialise()` RESTART the device, and `AudioEngine::audioDeviceStopped` -> `recorder.release()` -> `stopRecording()`, so ANY caller that reconfigures the device mid-take silently ENDS it. The guard existed in `applySessionSettings` and nowhere else; adding the rule immediately surfaced three more unguarded sites (the DEVICE panel's three combo handlers, `applySessionSampleRate`, and both new-session device pushes). **Guard at the MUTATION, not at the dialog launch** — the DEVICE panel is non-modal and can already be open when RECORD is pressed. Hooks aren't tracked by git: run `tools/install_hooks.sh` once per clone to get both gates pre-commit.
- `tools/design_audit.sh` is the CI gate (pre-commit hook) enforcing all of the above — **7 rules**, must stay CLEAN. Scope = `Source/{UI,Audio,Network,Capture}`, excludes `Theme/` + `Tests/`. The rules: (1) no raw `juce::Colour(0x..)`/`fromRGB`; (2) no bare `Colours::white`/`black`; (3) no raw `juce::Font`/`FontOptions`; (4) **withAlpha opacities must be `brand::alpha::` tokens — raw floats now FAIL** (stricter since the catalogue retirement); (5) rounded-rect radii are `brand::radius::` tokens (≤2px micro exempt); (6) no raw `.brighter()`/`.darker()` (use `brand::lift`/`sink`); (7) **spacing ratchet** — raw-int `reduced(N)` count must not grow past `SPACE_CEIL` (new spacing must use `brand::space::`; lower the ceiling as the tail migrates).

### Redundancy: a mirror must be provably somewhere else

- **A mirror writes `root/<sessionName>/Audio Files/Track_NN.<ext>` -- the SAME shape as the primary and backup.** So a root that is the session's PARENT resolves onto the take's own files: two `AudioFormatWriter`s, one path, for the whole show. With the picker opening at `~/Music` and sessions under `~/Music/Zynforge Sessions`, that was one click away. **`MultitrackRecorder::mirrorRootRejection` is the rule** (holds the session / inside the session / duplicates another mirror / is the backup root) and it runs in TWO places: the picker, for the message, and **record start, for the safety** -- a mirror config is persisted and outlives the dialog, and the *session* moves, so a root that was fine when configured becomes the session's parent the moment a session is opened from that folder. Validating only in the dialog is the same mistake as guarding a dialog's launch instead of its mutation.
- **A mirror that never OPENS creates no `Mirror` entry, so `anyMirrorFailed()` cannot see it.** Collisions and unreachable drives are counted into `getMirrorsSkippedAtStart()` and the recording banner reports them -- otherwise the engineer runs a whole show believing they have a copy they don't. `WriterChannel::mirrors` is built from `activeMirrors` (the filtered list), so **anything indexing a mirror by position must index `activeMirrors`, not `mirrorConfigs`** -- the session report did, and a single skipped mirror would have shifted every later root by one.
- **Writer failure state outlives the writer object.** Backup/mirror open and runtime failures are take-level latches; clearing failed writers at stop must not make status/reporting healthy again. `backupActive` means a requested backup is actually ready and has not failed, not merely that a path string exists.
- **An engine setter that can REFUSE must report the refusal, and the caller must not persist what was refused.** `MultitrackRecorder::setMirrors` returns false mid-take; `AudioEngine::setMirrors` is `[[nodiscard]]` and writes nothing when it does. Persisting a refused change made the settings file claim a redundancy the live recorder wasn't providing, and a restart made it look like a flake rather than a rule.
- **Do the thing first, then commit to it.** `ClickSettingsDialog` switched the live click engine OFF, saved that, and closed *before* calling `generateOrRefreshClickTrack` -- which refuses mid-take. Pressing Generate during a show silenced the drummer's click and rendered nothing. `generateOrRefreshClickTrack` returns whether it actually rendered; the dialog commits nothing on false.

### Network + remote entry points

- **Every inbound OSC socket uses `OscPacketReceiver` (`Source/Network/OscPacketReceiver.h`, 2026-10-29), never `juce::OSCReceiver`.** JUCE's parser recursed on nested `#bundle`s with no depth cap: one ~64 KB datagram from any LAN host overflowed the listener thread's stack. `oscwire::parsePacket` is bounds-checked, caps nesting at 8, and rejects bad sizes, truncation and trailing bytes; delivery stays on the message thread through the same Listener interface. A gate rule refuses `juce::OSCReceiver` as a type. Companion `/cmd` refuses JSON nested deeper than 16 before `juce::JSON::parse`. Console trim (`setTrackLiveInputGain`) drops non-finite values and clamps to -96..+72 dB; X32 head-amp wire values clamp to 0..1. Companion RECORD maps to `StartRecord` (never a toggle).
- **Remote surfaces do NOT touch `TrackState` directly.** `AudioEngine::setTrackMuted/Soloed/Armed` (and the `toggle*` variants) are the only sanctioned path for the companion server, OSC and MCU. They do two things a caller keeps forgetting: **mirror the stereo pair** (the invariant lived only in `ChannelStrip::pairState`, so every non-UI surface half-updated a pair) and **hold `MultitrackRecorder::getStructureLock()`** across the range-check-then-use.
- **`condemnAllStrips()` does not protect network threads.** It detaches COMPONENTS. A worker thread that range-checks `getNumTracks()` and then calls `getTrack()` is a TOCTOU against `removeLastTrack()` freeing the `TrackState` -- `captureStatus()` (called from a companion worker every 500 ms per client) walked the whole vector that way. Every structural change to `tracks` and every off-audio-thread read now take `structureLock` (recursive, so nesting from the message thread is fine). **The audio thread does not take it** and is unchanged by this.
- **A subscription EXPIRES.** The X32's `/xremote` lasts ~10 s. `ConsoleLink` sends `subscribe()` on connect and then re-sends it from a 1 Hz heartbeat (`kResubscribeMs`); the heartbeat also carries the reply-timeout watchdogs as deadline timestamps, so one timer serves both. Sending it once meant the entire pushed read tier -- scene recalls dropping markers, live name changes -- went dead ten seconds into every show, silently. The same heartbeat runs while ANY link is up (A&H too) and checks `transport->isConnected()`: a dropped Yamaha SCP / A&H TCP link is reported and disconnected, never shown as up. No auto-reconnect (a TCP connect blocks the message thread for up to 2 s).
- **Capture commands require the protocol handshake.** `CaptureServer` does not deliver anything except Hello until the client proves `kProtocolVersion`; a mismatch sends an error and closes. `CaptureLink`'s connection `shared_ptr` crosses threads only through atomic load/store.
- **Completion is "every distinct thing arrived", not "N replies arrived".** The patch stash decremented a counter per reply; since we subscribe to pushed updates, one unsolicited routing message finished the count with an incomplete stash, flipped the desk to card anyway, and left `exitSoundcheck` refusing to restore -- the desk stranded on card returns. Count distinct keys, and range-check every index that came off the wire.
- Remote security boundaries differ: companion HTTP and Generic OSC/UDP bearer tokens are plaintext on the network; OS entropy and log redaction do not provide confidentiality. Console dialects intentionally accept names/colours, trim-follow and markers without that token, while forbidding transport/arm/mute. Do not describe them as entirely read-only. Protocol-4 helper authentication preserves the existing controller until replacement authentication succeeds, but serialized candidate handshakes can delay attach/reconnect by roughly 1.7 seconds. See the audit residuals before widening network exposure.
- **Everything the companion serves needs the token, including anything WE write.** `SessionMirror` polled the primary's `/state.json` with no token for its whole existence: the companion 401s, the mirror parsed a plain-text 401 as JSON, and the UI reported "Mirroring..." forever. A client of our own API is still a client.
- **`StreamingSocket::waitUntilReady` takes the socket's readLock even for a WRITE check.** Never poll writability on a socket that has a reader thread parked in `waitUntilReady(true, ...)` -- the writer starves on the lock and every send fails. Bound a wedged write by making the write MUTEX timed (so other writers fail fast) and by closing the socket from another thread, which is how the rest of the codebase interrupts a stuck send.

### Stereo + view linkage

- A stereo pair is two adjacent physical tracks with `isStereo=true` on the L track. Every view (MIXER, EDIT, PATCH) must collapse the pair into one logical entry.
- Mute / solo / arm / gain / pan / colour / name / VCA / edit-group changes mirror across the pair automatically — never half-update.
- VCA gain + mute on a stereo pair: the R partner reads the L track's lane (in the audio callback) so both halves follow the curve. Pan stays per-channel so the stereo image isn't collapsed.
- **A stereo pair is captured as ONE interleaved 2-channel file** named for the L slot (`Track_NN.wav` with 2 channels); there is **no** `Track_(N+1).wav` for the R half. The pair still spans **two physical channels, collapsed into one logical strip** (L = index N with `isStereo`, R = index N+1) on every surface; only the on-disk file is single. This is the native-stereo model adopted 2026-06-13 (see the ADR in `decisions.md`) — it replaced the old "two mono files + `isStereo` flag" storage. How each layer handles it:
  - **Recorder** (`MultitrackRecorder`): the L `WriterChannel` opens one 2-ch writer (`openWriterAtPath(..., numChannels=2)`, `WriterChannel::numChannels=2`); the R slot gets an EMPTY `WriterChannel`. The drain step for the L writer reads BOTH FIFOs (`fifos[i]` + `fifos[i+1]`), stages them into the shard's `stageL`/`stageR`, and does one `writeFromFloatArrays(..., 2, n)`. Byte/roll/RF64 accounting multiplies by `numChannels`. The audio-thread push path + per-channel FIFOs are unchanged (meters, pre-roll untouched). Pre-roll dumps both channels into the 2-ch writer. **The R FIFO stays single-consumer even across a shard boundary**: the R slot's `WriterChannel` is empty, so whichever shard owns the R index skips it (`if (w.writer == nullptr) continue;`) and never drains its FIFO — only the L's drain (one thread) reads both FIFOs. So an odd-indexed pair split across two shards is still race-free; pairs do **not** need to be shard-aligned.
  - **Player** (`SessionPlayer`): `loadSession` sniffs `reader->numChannels`; a 2-ch file expands into TWO `Track`s sharing ONE `BufferingAudioReader` — the L track reads file channel 0, the R channel 1 (`useLeft`/`useRight`). One output stream per physical channel, so index→output is identical to the legacy layout.
  - **Offline render / bounce** (`AudioEngineClips.cpp::ArrangementSource`): `open()` resolves the channel — a 2-ch own-file → read ch 0 (L); no own-file but the prior slot's `Track_<track>` is 2-ch → read ch 1 (R). `bounceStereoPairToWav` thus pulls both halves from the one file.
  - **EDIT waveform** (`EditPage.cpp` `TrackRow`): when the pair is one file (`stereoOneFile`), the L lane draws file channel 0 and the R lane channel 1 from the same thumbnail (`drawLaneL`/`drawLaneR` → `drawChannel`), instead of two separate mono thumbnails.
  - **Import** (`MainComponentSessionIO.cpp`): a stereo source is written as ONE interleaved 2-ch `Track_NN.wav` (`writeStereo`), matching native capture; it spreads pan hard-L/R and **persists `session_mix.json` immediately**.
  - **Legacy compatibility**: sessions recorded the OLD way (two mono `Track_NN.wav` + `Track_(N+1).wav`) keep working everywhere — the player loads two mono tracks, `ArrangementSource` reads each own-file at ch 0, EDIT draws two mono thumbnails. The channel-sniffing makes both layouts transparent.
  - Other collapse points unchanged: **Meterbridge** skips the R half + gives the L meter a `setStereoPartner`; the **Export individual tracks** dialog shows one "(stereo)" row per logical strip and maps it back via `bounceStereoPairToWav`; `TrackExporter::exportStereoPair` still handles raw per-track stereo export with SR conversion.

### Session-scoped UI state

Some `MainComponent` state belongs to the SESSION, not the app, and every path that swaps the session out must reset it or it silently misfires against the new one. The live example is **`clickTrackIndex`**: `openSessionFolder`, `closeSession`, `createSessionFolderStructure` **and `applySessionTemplate`** all set it to `-1`. Missing one doesn't corrupt data (the name + playback-only-routing guard in `generateOrRefreshClickTrack` fails closed) but it *permanently disables Generate Click Track* for that session, because the guard aborts before the "create a fresh click strip" branch can run. Grep every assignment when adding another session-swap path.

### Persistence

- Anything the user can edit (track names, colours, routing, gains, stereo pairs, takes, cues, time signature, automation, VCA + edit-group assignments, markers, tempo) must round-trip through one of the per-session files. RAM-only state is a data-loss bug.
- Per-session files live under the session folder:
  - **`session_mix.json`** — the engine writes the full per-strip mix state (name, colour, gain, pan, mute, solo, monitor, arm, routing, stereo, VCA + edit group, **aux sends** — 4 slots of `{bus, dB, post}`) plus session-level tempo (`tempoBpm`, `timeSigNum`, `timeSigDenom`, `tempoMap`). Loaded on Open; its `trackCount` is exact, so the recorder grows or shrinks. A missing, malformed, or invalid file returns false and the open funnel sizes from loaded audio. **Aux sends are authoritative here, NOT global appProps** (the old `strip_send_*` appProps keys leaked routing across sessions; `setTrackSend` no longer writes them and `applyPersistedStripState` no longer reads them).
  - **`markers.json`** — markers auto-save on add / drop / rename / move; loaded via `markers.setContext(dir, sr)`.
  - **`<Name>.zfproj`** — `setlist` (cues, incl. each cue's `automation` snapshot), `playlists` (comp Takes; each clip carries `fadeCurve`, `sourceChannel` and a session-relative `sessionAudioFile`; legacy `audioFile` basenames are resolved against `Audio Files/`), `automation` (global lanes), `ui` (view / strip width / zoom).
  - **`session_groups.json`** is the older name for VCA + edit groups; superseded by `session_mix.json`. Don't reintroduce it.
- Interactive `Save`, cue edits, auto-save and STOP capture immutable serialized metadata on the message thread and enqueue it on the owned `SessionMetadataWriter`. Project read/merge/write and backup copies run on that worker; it must never dereference engine/UI state. Explicit saves retain ordered completion obligations; unstarted layout-only writes coalesce with bounded storage and do not persist unrelated mixer/cue edits. Success requires all requested writes and backup copies; compare current serialized content before marking clean, including edits outside the UndoManager. `saveSessionStateTo` remains synchronous for legacy transactional callers and refuses overlap with pending interactive saves. Cues' own automation is captured by `addCueAtTransport` / `updateCueAtTransport`; recalling a cue **clears** every lane first, then loads the cue's snapshot (so a cue without a track-N entry doesn't leave another cue's curve on track N).
- **Auto-save** (`MainComponent::serviceAutosave`, driven from the 10 Hz timer) enqueues a full immutable snapshot on every user-set interval (appProps `autosaveMinutes`, 0 = off, default 5; picker is Session ▸ Auto-Save & Backup…). Do **not** gate it on undo count: recording, routing, cue recall and imports deliberately bypass that counter. The backup itself is `zynforge::sessionbackup::writeSnapshot` (`Source/Audio/SessionBackup.h`, headless-tested): a **full backup session** — a timestamped `Session File Backups/<Name>_<stamp>/` folder copying the session-defining files (`.zfproj`, `session_mix.json`, `session_settings.json`, `markers.json`), **never the audio**, pruned to 10. Save the live metadata first, then snapshot it; advance the clean/last-attempt baseline only if both succeed. On failure, warn and retry after 15 seconds. These are metadata backups; audio is written separately, and restoring old metadata cannot undo a committed punch. Independent media backup/recovery remains necessary.
- Local async STOP uses `AudioEngine::stopRecordingAsync`: capture publication changes once, then the engine owns drain/close/splice/report and reader preparation, the message thread installs prepared state, and owned work retires old readers before completion. Preserve its finalization lease across deferred device callbacks. Main holds the same operation pending through metadata; do not infer idle or allow structural mutation from recording=false alone.
- During async STOP metadata finalization, keep capture/session mutations guarded while servicing UI navigation. Remote STOP retains its first-tap confirmation, then returns false with `finalization pending`; retry after completion returns true only for a successful finalization, while a failed result stays latched. Do not infer finalization success solely from `!isRecording()`. Save & Continue / Save & Close / Save & Quit reserve edits and execute their continuation only after successful, still-current persistence. Destruction drains owned persistence work and retires queued UI callbacks using `SafePointer`.
- Snapshot retention orders by timestamp plus numeric monotonically increasing collision sequence, including legacy `(N)` folders and backward wall-clock jumps. Refuse nonpositive retention before touching files, never follow/prune linked snapshot roots/candidates, and preserve unrelated journals. The inherited October 5 patch is covered by all three full 563-group follow-up suites; normal startup was observed, while interactive and physical acceptance remain pending; see the audit report for actual evidence.
- `.zfproj` carries a `formatVersion` field. Treat its absence as v1 and fall back gracefully.
- Per-strip state used to live in **global** `appProps` keyed by index, which leaked between sessions. New sessions / freshly-grown strips now wipe the per-index `appProps` overrides (see `clearStripOverridesRange`); the session files are authoritative.
- Bulk strip reset/range clear batches each StripNames/StripColours/StripGains/StripRouting domain: replace its shared-file cache once, remove all covered keys, then save once; appProps has its own replacement/write. Preserve sibling updates/deletions and unknown keys. Clear both legacy and `strip_send_<index>_<slot>_{bus,dB,post}` keys. The deterministic `Settings batch reset audit` counts reloads and checks persisted/in-memory semantics; S4 targeted Release passes all four groups, with reset/range/growth reloads 5/5/10; all three full follow-up suites also pass. `resetForNewSession` separately batches 27-track defaults to five settings transactions, covered by Review capture repairs.
- **Five `PropertiesFile` instances share ONE `.settings` file** (`appProps` + `StripColours`/`StripNames`/`StripGains`/`StripRouting`), and a whole-file save rewrites every in-memory key. So before mutating+saving, each writer **reloads to REPLACE, not merge** (`clear()` + `reload()`, guarded on the file existing — `StripGains.cpp::reloadReplace`, `AudioEngine::reloadAppPropsBeforeWrite`). A plain `reload()` *merges*: it never drops a key another writer just deleted, so the deleting module's next save resurrects it — this is what made a cleared pan/gain come back on the next `setStripCount` (the "clear didn't stick" bug, locked by the `clearAllStripOverrides` test). Never use a bare `reload()` on one of these shared files before a save. **Corollary for tests + callers:** a `setValue()` that isn't followed by `saveIfNeeded()` is thrown away by the next `reloadAppPropsBeforeWrite()`, because reload-to-REPLACE clears the in-memory copy first.
- **`removeStripAt` must shift EVERY per-index key, not just the Strip\* module ones.** The persistent stores key by array position, so deleting a strip from the middle has to pull `name/colour/gain/pan/in/out` **and** the appProps-owned `strip_stereo_N` + `strip_uid_N` down a slot, then clear the orphan tail. Missing the last two re-formed stereo pairs on the wrong strips and re-stamped the stable IDs on the next `applyPersistedStripState()` — which breaks every cue snapshot, since cues reference strips by `stripId` precisely so they survive a reorder. Locked by *removeStripAt shifts stereo flags and strip UUIDs*.

### Stable identity

- Cue strip snapshots use `TrackState::stripId` (a `juce::Uuid`). Existing automation lanes and cue automation use track indices and must be explicitly remapped by the shared reorder operation.

### Dialogs + prompts

- Every prompt that has a text or number field calls `dialog::primeNameEditor(aw, "fieldId")` after the buttons are added: it grabs focus, selects all text, and wires Enter in the field to `exitModalState(1)`. Every AlertWindow prompt in this app uses result code **1** for OK / Apply / Save / Create — don't break that convention.
- For custom `juce::Component` dialogs (`AddTracksDialog`, `NewSessionDialog`), do the equivalent by hand: `setSelectAllWhenFocused(true)` + `grabKeyboardFocus()` (deferred via `MessageManager::callAsync`) + `onReturnKey = [this]{ commit(); }`.
- **Never capture raw `this` in an async menu / modal callback.** `showMenuAsync` and `enterModalState` both OUTLIVE the click that opened them, and a floating dialog can be closed while one is up — use `juce::Component::SafePointer<T> safeSelf (this)` and re-check it inside EVERY nesting level, including the inner modal (`MarkerListDialog` and `TimelineStrip` were the two that didn't).
- **A FLOATING (non-modal) dialog must re-derive its own enablement from live engine state**, not from what was true when it opened. `AudioDeviceDialog` can be sitting open when RECORD is pressed, so it watches `engine.isRecording()` on a 4 Hz change-gated timer, greys its four device combos, and refuses every mutating path (including the Cancel/destructor revert, which also restarts the device). Static enablement computed in the constructor goes stale the moment the show starts.
- **A dialog control must do what it looks like it does.** Session Properties' "Session name" was an editable field writing a `name` property that only that same dialog ever read back -- the folder name is what the title bar, status line, recent list and `.zfproj` use. It's now read-only with a pointer to Save As. A field that appears to rename and doesn't is worse than no field.
- **Export defaults to the SESSION's sample rate, not 48 kHz.** `TrackExporter` has a deliberate bit-exact path when source and destination rates match; hardcoding 48 kHz sent every 44.1 / 88.2 / 96 kHz session down the resampler by default. `ExportDialog::launch` takes the rate, preselects it (adding it to the list if non-standard) and states whether a conversion will happen.
- **`compactPath` only substitutes `~` when the path is actually under the home directory.** An external record drive is `/Volumes/...`; labelling it `~/Volumes/...` on the control that tells the engineer where the take lands is a trust-destroying lie for zero pixels saved.

- **Product / UX direction changes** → `design.md`.
