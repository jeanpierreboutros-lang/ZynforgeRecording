## Project

JUCE 8 / C++20 / CMake, macOS-only (Universal; no Windows or Linux port, owner decision 2026-10-31) multitrack recording + playback application with virtual soundcheck. Sibling to the ZynForge Live plugin-insert host.

**Stack:** JUCE 8.0.4 (via CMake FetchContent), C++20, CMake (Xcode generator), Apple Silicon + Intel universal build, macOS 12.0 deployment target. Native macOS sans-serif UI + bundled JetBrains Mono.

## Workflow rules — non-negotiable

1. **After every code change**, update `CLAUDE.md` + `README.md` to reflect what's actually in the codebase.
2. **Build** with `cmake --build build --config Release` after every change. Don't claim success without a successful build.
3. **Smoke-test** by launching the app from `build/ZynforgeRecording_artefacts/Release/`. Watch RSS, CPU, and `~/Library/Logs/DiagnosticReports/Zynforge*.ips`.
4. **Commit and push to `origin/main`** after every change. Auto-push is the policy — no asking.
5. **Do not name, credit or compare to** any competing recorder anywhere — not in code, comments, docs, or commit messages.
6. **This is a recorder + virtual soundcheck**, not a mixer. No plugins. No talkback. No in-the-box effects.
7. **MIXER / EDIT / PATCH views are linked.** A change in one must reflect in the other two. Stereo pairs collapse to one logical strip in all three views.

**Undo model.** Clip edits push `ClipSnapshotAction` immediately. Mixer ops (fader/pan/mute/solo/rename/recolour/routing) have NO per-gesture wiring — `MainComponentEdit.cpp::pollMixerUndo()` (from the 10 Hz timer) compares an allocation-free mixer **fingerprint** and records ONE `MixerSnapshotAction` once a change settles (~300 ms); the JSON snapshot is built only when a baseline is taken or a step committed, and a take only marks the baseline stale. A bulk mixer action (Solo selection, Arm selection, strip paste) takes `beginMixerUndo()` first and `commitMixerUndo(label, before)` after the change: `MixerSnapshotAction` reads its "after" state when performed, so pushing it before the change records nothing and leaves the real change for the settle poll to add as a second step. Snapshot, restore and fingerprint share one field table in `Source/UI/MixerSnapshot.h` -- add a mixer field there, never to one of them alone (*Strip lifetime and mixer fingerprint* pins it); `editUndo` flushes any pending change first, and re-baselines after undo/redo + on session open. **Recording is deliberately not undoable.** Keyboard shortcuts in `MainComponentKeys.cpp` match on **key code**, not `getTextCharacter` (unreliable under Cmd on macOS); JUCE doesn't wire native accelerators for these non-command menu items, so the keyboard handler is the real path (the menu's "⌘Z" hint is display-only). Initial `MixerSnapshotAction::perform` captures the already-applied gesture without calling `applyAll`; real undo/redo still replays state. Keep the zero-redundant-reload regression.

**One timeline span for the whole EDIT view (2026-08-12).** `Source/UI/EditTimeline.h` holds `kNotionalEmptyLaneSec` / `notionalEmptyLaneSamples(sr)` — the span a lane and the ruler cover when the session has **no audio yet** (5 notional minutes, at the DEVICE rate). The ruler, the edit cursor, the markers lane and `TrackRow::laneTimelineSamples()` all route through it. They used to disagree (300 s vs 60 s vs a hardcoded `48000 * 60`), so a position picked before the first take under the ruler's 2:30 mark was stored at 0:30 — the exact paint-vs-hit-test mismatch `laneTimelineSamples()`'s own comment warns about. The same header holds **`matchingClipIndex`**: a clip INDEX is per-track, so a peer's clip is found by exact span first (counting identical stacked spans in order), then the parallel index on a stereo partner that drifted, then `clipIndexAtMidpoint`, which takes the clip under the source's midpoint sharing the most of its span. Midpoint alone landed on whichever overlapping clip it fell in.

**macOS menus + session loading (read before touching either).** `MainComponent` is the `MenuBarModel`; macOS caches each item's greyed/enabled state until `menuItemsChanged()` is called, so `MainComponentMenu.cpp::refreshMenuStateIfChanged()` polls a signature of every menu-gating condition from the 10 Hz timer — **if you add a menu item whose enablement depends on state, add that condition to the signature or it freezes greyed.** **Menu dispatch is a table (`Source/UI/MenuCommandTable.h`), built by `MainComponentMenu.cpp::registerMenuCommands()`.** Register each static item with `m.add (id, handler)` and each generated family with `m.addRange (first, last, handler(offset))` -- currently `200–249` templates and `2000–2099` template-as-default. (The old if/else chain let a range branch swallow later exact ids and kept handlers for ids nothing built any more. OSC dialects live in Control Surfaces, LTC/MTC sources in Timecode Sync, per-track export in Export Audio.) `menuItemSelected` itself only applies the LOCK / session-I/O guards and dispatches. The console items' enablement (`consoleLink.isConnected()` + patch state + **profile capability** `canRepatch`/`canCaptureGains`) is part of the menu-state signature. **Console control is a four-layer stack (2026-08-13).** `ConsoleTransport` (bytes + framing: `OscUdpTransport`, `TextLineTransport` for Yamaha SCP, `MidiTcpTransport` for A&H) -> `ConsoleDialect` (which address means what, and `parse()` -> `ConsoleEvent`) -> `ConsoleProfile` (transport kind, capabilities, display metadata) -> `ConsoleLink` (pure state machine, knows no protocol). **Capabilities are tiered by RISK, and the split is the whole design:** the READ tier (`canReadNames`, `canReadScenes`) cannot change a desk and is where nearly all the value is for a recorder — names label the session, scene recalls mark a take. The WRITE tier (`canRepatch`, `canCaptureGains`) can wreck a show. **`ConsoleLink::canWrite()` gates every write on `profile.dialectTrusted || dialectConfirmed`.** `dialectTrusted` is a claim about the ADDRESS MODEL (documented + pinned by tests — true only for X32/M32); `dialectConfirmed` is set when the console answers the connect-time probe. So a dialect written from published docs with no hardware to test on is safe to ship: it degrades to read-only, never to writing a guess. **Never set `dialectTrusted = true` for a dialect you haven't pinned with encode/parse tests**, and never claim a capability whose encoder is null — `ConsoleTransportTests` fails the build on both. Don't fake repatch for a desk we can't talk to; see the 2026-06-10 and 2026-08-13 ADRs in `decisions.md`. The menu bar is `File · Edit · Track · Session · Help` (Edit = timeline/audio; Track = channel management). Every session open — File ▸ Open, Welcome, launch auto-reopen, command line, Finder and a second-instance `.zfproj` open — funnels through `MainComponentSessionIO.cpp::openSessionFolder()`. It condemns the old UI, stops playback, calls `clearSessionState()`, loads audio, loads the exact mixer count (grow **or shrink**), then restores playlists after the player's default-clip seed. Missing or malformed `session_mix.json` falls back to the audio count. A mix that lists zero strips over a session that has audio is treated the same way. Export reads recordings from `Audio Files/` (legacy root fallback), not the session root.

**Session replacement and long file operations (2026-08-18).** New/Open/CSV/Console/template/Finder paths call `confirmSessionReplacement` before replacing an active session; save failure cancels the transition. A template choice creates a new session and only then applies the layout; the configured default template also applies in both New flows. Save As requires a new or empty folder, saves the source first, performs a cancellable clone, and calls `openSessionFolder(dest)` only after success — never merge folders or pin a partial destination. Relocation uses the same owned `exportThread`, saves first, rejects descendants/existing targets, and treats a complete cross-volume destination as authoritative even if old-folder cleanup fails (surface that exact warning). `sessionIoBusy` + `AudioEngine::sessionTransitionActive` gate recording, playback, strip mutations, bounce and competing transitions while copy/move/bounce owns session structure. Destructor/quit cancels and joins; never detach these jobs.

## Implementation invariants

### Core (September baseline, October audit updates)

- RECORD runs in stages (`MainComponent::onRecordClicked`): `handleRecordPressDuringTake` consumes a press during a take; `prepareRecordStart` runs **every** refusal (no tracks/device/inputs/arms, StereoMix sources, clock mismatch, disk space) before anything changes; `cursorPunchNeedsAnswer` then stops to ask before a stopped cursor punch; only then `runRecordPlan`: `applyRecordAutoRouting` and exactly one of `startDaemonTake` / `startSelectionPunch` / `startLocalTake`. Never add a side effect to `prepareRecordStart`.
- `isRecording()` includes daemon capture. Arm changes are refused while rolling; the recorder freezes `captureArms` for both capture and FIFO gates. Never rely solely on current UI arm state.
- `reorderTracks` is the shared media/state transaction for moves and deletion. It preserves complete stereo blocks, archives removed audio, remaps UUIDs/cues and clears stale undo/clipboard state. Do not reintroduce ad-hoc swap renames or manual per-index key shifts.
- It is also expensive (stops the player, detaches the audio callback, renames every take file, rewrites session documents — all on the message thread), so **one user gesture = one `reorderTracks` call**. Build the complete order with `Source/Audio/TrackOrder.h` (`logicalBlocks` / `moveBlock` / `flatten`; a stereo pair is one block) and commit it once — the EDIT swatch drag previews via `EditPage::updateReorderPreview` and commits in `mouseUp` via `commitReorder`. Never call it per pointer step. `MainComponent`'s `onTracksReordered` handler is the single place that rebuilds strips, refreshes EDIT rows (asynchronously — it can run inside a row's own `mouseUp`) and rescans waveforms after any reorder. `EditPage::refresh()` rebuilds on a changed logical **layout** (`TrackList::matchesLayout`), not just changed counts.
- Keep `Session File Backups/reorder_*` journals and metadata available for recovery. `Removed Tracks/<uuid>` contains retained audio, not disposable cache. Ordinary backup snapshots contain metadata only; these transaction folders have different retention semantics.
- Playlists distinguish initialized-empty from absent. Preserve them across same-session imports/reloads. Persist source channel and session-relative media path (`sessionAudioFile`, legacy `audioFile` fallback); missing explicit media stays silent.
- Persist strip UUIDs in `session_mix.json`; commit settings UUID changes after other property writers have reloaded.
- The installed build (`281c6c0`, both Macs, 2026-10-29) uses protocol 4: require a compatible Hello and mutual HMAC-SHA256 authentication before delivering commands, then configure device/rate/routing/arms/pre-roll/redundancy before Start. Both Macs and the current distribution package have the matching `443c769` protocol-4 pair. Keep GUI/helper upgrades paired and do not silently adopt an old helper. STOP distinguishes command acceptance, capture completion and finalization health; never claim idle from a button click or kill a daemon from stale status. Package the matching daemon per INSTALL.md.
- A fresh take never replaces an existing `Track_NN` in any supported container. Existing media requires an explicit continue/punch path even when the session is unreadable. Check before opening any writer, not after.
- Backup/mirror copies count as active only after their directory and writers open. Latch start/runtime failures through stop, and group disk byte rates by physical volume when estimating remaining time.
- Long analysis/edit operations capture immutable state on the message thread, render on a background worker, and publish only if the session and source arrangement are unchanged. They refuse both local and external recording.
- Marker naming callbacks resolve runtime identity after sorting and asynchronous completion (`MarkersManager::indexOfId`, used by the ruler's and the marker list's rename and delete). Template-default IDs occupy 2000–2099.
- **Alarms belong in `alarmBanner`.** `updateCaptureWarnings` builds the text and adds conditions as before; `refreshAlarmBanner` decides what shows: `activeCaptureWarning`, then a failed finalization (it stands after STOP until the next take or session), then a device-rate mismatch during a take, then a refused RECORD (`showRecordRefusal`, clears after 8 s, on the next press, or when a take starts). A message with no `!` is an amber notice; everything else is red. The banner has its own row and takes no clicks: never let it cover the transport.
- **A way out of a session calls `forgetSessionUiState` beside `engine.clearSessionState()`.** It holds what the engine cannot reach: a latched failure, the cue list and setlist bar, a running scan.
- **LOCK and custom mouse code.** JUCE delivers `mouseDown` to a disabled component, so `setEnabled (false)` stops only stock widgets. Any hand-written `mouseDown` that opens a menu or mutates must check `isEnabled()` or `engine.areControlsLocked()`, at the click and again when an async menu returns. Rebuilt strips take the lock from `rebuildStrips`; EDIT rows and ruler go click-through through `setReadOnlyWhileRecording`.
- Console repatch and head-amp restore refuse during a take (`refuseConsoleWriteDuringTake`); capture of head-amp gains is a read and stays available.
- The header tab and the menu open one tracked Patch or Meterbridge window (`openPatchWindow`, `openMetersWindow`). Never launch a floating panel without keeping its pointer: LOCK and the 10 Hz reaper reach only tracked windows.
- `TrackState::referenceMedia` stays for the recorder alone. Nothing sets it except loading a session from an earlier build that holds a generated click bed (`loadSessionMixFrom`, including the older case of a strip named Click with input None and no flag). It is written back on save. `getCaptureLengthSamples` and the recorder's continue scan skip such a strip: without that, RECORD after STOP would start at the end of the bed, up to three hours later, and pad every take with silence. The strip is otherwise ordinary: it has its R and I buttons and Detect Songs listens to it.
- With no session and no loaded player, `checkDeviceSampleRate` follows the device: there is no session rate to disagree with.
- Pre-flight's disk verdict and RECORD's refusal share `recordHeadroomBytes` (`RecordPosition.h`).
- `setBackupDirectory` returns false, and persists nothing, when the recorder refuses.
- `toast.showNow` is for a prompt with its own deadline (Tap STOP again). Everything else queues.
- `AudioDeviceDialog::closeSelfOwned` runs first in `~MainComponent`: JUCE would otherwise delete that modal after the engine it uses.
- **Nothing changes the arrangement under a take.** Every clip and take setter refuses while `AudioEngine::isArrangementFrozen()` (recording, or an async STOP still finalizing). The UI lock stops new gestures, not a menu or dialog already open, so a row's menu and dialog callbacks also ask `timelineEditAllowed()` at the moment they act.
- **Long clip jobs check the track generation.** Consolidate names tracks by index, so it records `getTrackGeneration()` at launch and publishes nothing if it moved: another channel at that index often holds a clip of the same position and length. Row Consolidate is a session job on the host (`consolidateTracks`), so it survives the row being rebuilt and owns its undo snapshot.
- **Strip selection and active row are positions in one layout of one session.** `syncStripSelectionScope` (from `rebuildStrips`, which every session swap and layout change reaches) clears the selection when the track generation or session changes. `moveSelectedStrips` re-stamps the generation because those strips moved on purpose. `EditPage::refresh` clears the active row at the same moment it clears the clip selection.

### October 3 audit invariants

- A capture boundary synchronizes pre-roll buffer swaps and transport publication. Allocate/free buffers and perform disk writes outside that boundary; detached histories share one live seam. Continuation padding is measured per destination.
- `.zynforge-capture-id` identifies primary capture media; backup/mirror `.zynforge-primary` metadata binds the copy to that identity and primary path. Never adopt a non-empty unverifiable copy or truncate an unexpected writer target. A relocated primary retains its identity; a live fork must use a separate backup destination.
- Arrangement source failures must propagate to export/edit callers. Locked consolidation ranges fail before replacement. Legacy root-level media remains readable after creating Audio Files.
- Session clear resets mixer state. Remote controls honor the engine lock, including queued MCU callbacks.
- Every settings writer uses SettingsFile.h. Test isolation is process-wide and irreversible; `--isolated-settings` provides an isolated normal-UI smoke launch. Keep the October regression suite in the CMake target.

### Feature invariants (distilled from the September–October checkpoint log)

The dated paragraphs these came from are preserved verbatim in [docs/history/CLAUDE-status-log-2026-09-10.md](docs/history/CLAUDE-status-log-2026-09-10.md). The rules below are what still binds the code.

**EDIT waveform + navigation**
- Post-STOP overview: at long horizontal scales `TrackRow::drawOverviewWave` draws the median of 16 thumbnail peak windows per screen column as the body and their maximum as a thin marker; it falls back to JUCE's native waveform at detailed scales or before the scan completes. The cache holds what the last two paints drew (`ageOverviewCache`), so it is bounded by the screen, and is cleared when source files or thumbnails change. A fixed size evicted its own entries on every repaint once a row showed more clips than it had slots. Display changes never touch the saved audio path; preserve stereo file-channel mapping and refresh thumbnail data before marking an on-disk cache final.
- Finalized sessions zoom to `kMaxTimelineZoom = 512`; an active recording stays at 16× to protect its growing component width. Bound grid ticks to the visible viewport at deep zoom.
- `LivePeakHistory` keeps a bounded recent ring of original 256-sample peaks beside its downsampled whole-take overview, and the EDIT row queries recorder-bin ranges so the recording edge keeps detail after hours. Keep the ring bounded, keep its absolute-bin mapping across wrap and downsampling, aggregate incoming bins after each downsample and retain the real elapsed sample count. Never infer the live sample position from the overview length, and never restore the old `recBinSamples *= 2` per-overflow path (it inflated displayed time and overflowed on long takes).
- `TimelineFollowState`: a manual horizontal pan or time zoom pauses FOLLOW; the FOLLOW toggle or a new transport pass resumes it. Vertical track scroll and waveform-amplitude zoom never pause it. H+ and H− are reciprocal and return exactly to 1× fit-to-take — no zoom deadband. Ruler, header and minimap stay synchronized through the viewport scroll callback. Never scan growing take files just to draw the live waveform.
- While capturing, `EditPage` stays enabled: `setReadOnlyWhileRecording` makes rows and ruler click-through (clip/marker edits locked) while zoom, scrolling, minimap and FOLLOW keep working. `recordingTimelineSpanSamples` supplies one span to ruler, rows and playhead; `recordingContentWidth` widens the list against the pass's initial span (five minutes for a fresh take); clip the live-envelope draw to the visible area. A zoom during capture waits for the normal stop-save to persist layout — no project-file write on the take volume.

- Crossfades pair clips in timeline order (`timelineCrossfades`), not list order.
- **Every clip command resolves its targets in `Source/UI/ClipEditTargets.h` (2026-11-01).** `peerTracks` is both halves of a strip and every edit-group member; `closure` grows a selection to its peers, one hop only (with members split differently, a second hop lands on a clip nobody chose); `ripplePlan` gives every track of a family the same spans, last first, and `rippleSpans` runs them as one edit: the save after an edit starts a metadata job that refuses the next edit, so one edit per gap would stop after the first. A command never takes its own (track, index): EDIT paints only L's list, so a half-edited pair looks right on screen while it plays out of time. A nudge uses one delta bounded by every target; a locked target refuses Delete, Duplicate, Ripple and Cut whole. A drag holds the peers it resolved at its first step (`dragPeers`).
- **The clip selection follows the clip (2026-11-01).** `EditPage` stores (track, `Clip::selectionId`), and every read goes through `followSelectedClips()`. The id is runtime-only and never saved, stamped fresh on each selection. An edit that shifts the list keeps the selection on its clip; undo rebuilds clips with id 0, and a split leaves two clips sharing one id, and either way the selection drops rather than naming a neighbour. `clipSlice` copies the id, which is what makes a split ambiguous; `duplicateClip` clears it.
- **A row draws the file a clip plays.** `laneWaveFor` resolves one lane of one clip the way `ArrangementSource` does; a clip with its own `audioFile` gets its own thumbnail (`ownThumbs`, dropped when the row's files change). A mono row draws one channel of its file, resolved through `getTrackAudioFile`, so an unlinked R row draws its channel of the shared file.
- **`WaveCache.wfm` lives in `Source/UI/WaveCacheFile.h` and runs on `EditPage::waveCacheThread`,** a `SerialWorker`. A job runs while `waveCacheWork` holds its number; changing the number cancels it at the next chunk. A take start and a session job cancel a save. `atomicfile::writeWith` means only a complete cache replaces the file. A section longer than the file left is a truncated cache: delete it, don't load it. Rows stay blank while a session's peaks load, so the previous session's waveforms never sit under this session's names. `rescanWaveforms` deletes the file on that same thread, after any save in flight: a rename keeps modification times, so nothing else notices stale peaks.
- **After STOP only the rows the take wrote rescan** (`capturedRows`, snapshotted when the take rises; arms are frozen during a take). Only a row that captured holds its live envelope.
- **The scan threads stop in `~EditPage`, not in the cache's destructor.** See *No thread is killed* under Real-time discipline.
- **Tab does nothing outside a text editor, on purpose.** `MainComponent` consumes it, so keyboard focus never walks onto a routing combo or a transport button, where the next arrow or Return would change it mid-show. Shift+Tab is not consumed (JUCE `KeyPress == int` excludes modifiers) and still walks focus.
- **EDIT draws only what is on screen.** Every JUCE thumbnail draw goes through `drawThumbnailVisible` (trimmed to visible columns); the Markers lane backdrop is drawn per clip at its timeline span. The EDIT page timer ADDS its recording state to the host's read-only lock (never overwrites it), drags in flight stop when the lock engages, and waveforms rescan only after an async STOP has finished finalizing. The selection clears when the track generation or the active session changes.

**Engine and playback (2026-10-29 bug hunt)**
- **`inputRouting` is the REQUESTED patch and is what every save writes.** The wrap onto a smaller device (`i % numInputs`) happens only where routing is live: the callback, MIXER/EDIT/PATCH display, record-start checks and the daemon config (`TrackState::effectiveInputRouting`, `AudioEngine::getEffectiveInputRouting`). Never store a clamped value back.
- **LTC LOCK means decoded frames.** `TimecodeChase` counts a frame only with exactly 80 clean bits between sync words, takes fps from the sync-to-sync period (29.97 via the drop-frame flag), needs 3 consecutive labels to LOCK and drops LOCK 0.25 s after frames stop. Only the selected chase source feeds/reports liveness; `ltcSourceStrip` follows `reorderTracks`.
- `SessionPlayer` advances position and wraps loops with a compare-and-swap from the block's start, so a locate during render is never overwritten; loops wrap at min(loop end, session end). `mix::stripDb` takes the fader alone: at its -60 dB floor the strip is off. `StripGains` writes the first change at once and coalesces a burst (<= every 250 ms, flushed on destruction). Linking a pair copies L's mute/solo/arm/monitor/fader/edit group/output mute/stream send to R and patches R to L+1.
- **A stereo strip's STREAM send is one control.** `setTrackStream` writes both halves under the structure lock. `ChannelStrip` no longer writes the atomic itself: it calls `onStreamSendChanged`. `loadSessionMixFrom` repairs a saved pair from L, because the strip shows L.
- **Trim-Follow needs a reference.** `TrackState::liveInputGainKnown` / `captureInputGainKnown` say a value came from the desk; 0 dB is a valid preamp, so the value cannot say it. `mix::trimFollowDb` is the one rule: no reference, 0 dB; otherwise live minus capture, limited to +12 / -30 dB. `snapshotCaptureInputGains` runs when a take really starts, local (`startRecording`) or daemon (`startDaemonTake`), and a strip the desk has not reported gets no reference. A session from before the flag reads a stored 0 as no reference. Trim-Follow never touches live input: the callback's `trimFollowDb` is 0 for every strip during a take with the transport stopped, and for armed strips during a punch. `getTrimFollowNotice` / `getTrimFollowUnreferencedCount` feed the status line and the Session menu item.
- **The stream bus and StereoMix ignore solo.** `mix::streamAudible` takes the strip mute only; solo is monitoring. The main bus gate stays `mix::audible`.
- **A mix bus stays off an output a strip is patched to** (`mix::busHeldOffOutputs`), on a device with more than two outputs, unless the engineer turned on Session ▸ Recording & Sync ▸ Let the Mix Share Outputs With Patched Strips (`mixMaySharePatchedOutputs`, appProps, default off, menu 991). It is decided from the patch, not from what is audible, so a muted strip cannot let the mix drop onto its channel. Meters and LUFS keep running. The master MUTE still kills the selected pair whether the mix reaches it or not. The callback publishes `masterHeldOff` / `streamHeldOff`; the master strip and the status line read those, so the UI shows what the callback did.
- **Master output Off is `setMasterOutputs (-1, -1)`.** Every reader of the pair goes through `mix::masterOutputs`. A device smaller than the saved pair gets its last pair, or both sides folded to mono on one output; never clamp the two sides separately.
- **Stream bus output is per session** (`streamOutL/R` in `session_mix.json`, menu 990). An older session has none. `clearSessionState` clears it, so a route never leaks onto the next session's outputs.
- **`PlaybackReader` is the player's reader, not `juce::BufferingAudioReader`.** It keeps a read window, a CUE (`cue`) and a second read position for overlapping clips from one file, and `isBuffered` tells the player what is in RAM. `read`, `cue`, `prepareAt`, `isBuffered` are atomics and memcpy, on the audio thread. Only its background thread touches the source. A block is pinned while copied; the background thread blanks `start` before it reads the pin. Never change that order.
- **Every track enters a jump together.** `SessionPlayer::renderBlock` treats any start that is not the last block's end as a jump and holds it, silent, position unmoved, until `prepareJump` says every track has the target in RAM, up to 2 s of device samples, then plays anyway so a dead source cannot hang the transport. `cueUpcoming` cues the loop start and the next clip 1.5 s ahead, every 8th block, so a wrap usually needs no hold. A seek-locked player (a punch) never holds: the capture clock is already running and a paused playhead would put the take late against the old audio. Consequence for tests and tools: after a far locate, the position stands still until the readers have it.
- **MTC is read as whole runs.** `feedMtcQuarterFrame` collects 0 to 7 (or 7 to 0 in reverse) in sequence, starting only on the first message of a run; anything out of sequence drops the run. The published time is ONE atomic word (`TimecodeChase::label`), so no reader can tear it.
- **Chase is relative to the session's start timecode** (`chaseStartLabel`, `chaseStartTimecode` in `session_mix.json`, set in Transport Sync, or from the first take's BWF stamp). `getChaseTargetSamples` can be outside the session. `getChaseParkReason` is the single test: `serviceTimecodeChase` then leaves the playhead alone, stops what chase started once, and says why. House timecode across midnight wraps.

**Capture, punch and continuation**
- **BWF time reference (2026-10-31).** `bext` TimeReference is samples since midnight of the file's FIRST sample. `Source/Audio/BwfStamp.h` owns the walker and the patch. A file opens with an estimate (JUCE keeps the bext block from open and rewrites it on every flush, and writers open before the first live block), so a crash survivor has a usable time. `stampTakeFiles` then patches the exact value: after every writer closed, after the punch splice and lead-ins, before `publishSessionReport` starts the hash thread. Keep it there: the hashes must describe the final bytes. **That 8-byte patch is the ONLY write ever made to a closed capture file**, and it is a compare-and-swap against what was stamped at open (`WriterChannel::stampedParts`), so a file that is not what we wrote is left alone. A refusal goes in `timeReferenceStampFailures` and never latches a capture failure: the audio is fine.
- **Where the time comes from.** `TimeAnchor` pins a time of day to the high-resolution clock. `AudioEngine::startRecording` hands the recorder a hint only when chase is live (`getTimecodeAnchor`); otherwise the recorder anchors the wall clock. The recorder never touches `TimecodeChase`. The audio thread stores only the first live block's clock reading and size; nothing there converts time or calls localtime. The daemon's hint travels in the Start command's `configuration`; `mach_absolute_time` is shared between the two processes. A label is read at RECORD and can be up to a frame old on LTC, two on MTC, so a timecode stamp is good to about a frame, never to a sample.
- **Part stamps.** Each pass stamps its own real time. An auto-split part stamps the pass start plus the frames this pass wrote to that copy before it, per destination (copies in different formats split at different frames). A continuation pass is a new pass. Pre-roll subtracted is what was written (`preRollHistorySamples`), not what was asked for.
- **A punch keeps the take's stamp.** `splicePunchFromReader` carries the base's bext fields (`bextFieldsOf`; `ConcatReader` exposes the first part's), because a spliced file begins with the base's first sample. It used to write no metadata at all, so every punched WAV lost its bext. `splicePunchedTracks` removes spliced and rolled-back copies from the stamp list; a track newly armed in a punch has no base and takes the punch's time. Silent lead-in parts carry no bext.
- **Channel names in raw files.** Files stay `Track_NN.wav`. The bext Description is `sTRK1=<name>` (and `sTRK2=` for the right channel of a stereo file) on CRLF lines, then the session/take text, at most 256 bytes on a UTF-8 character boundary (`bwf::channelDescription`). Names are capped at 64 bytes so the take text always survives, and control characters are replaced because names arrive from console OSC. They are read once at record start into `WriterChannel`: a roll opens a part on a writer thread, which must never read `TrackState::name`. JUCE 8.0.4 cannot emit an iXML TRACK_LIST: `IXMLChunk::createFrom` writes only the ASWG keys, so there is no iXML, and we never append to a closed file to add one.
- **Dead-channel alarm.** `Source/Audio/ChannelAlarm.h`. Quiet is normal, so it keys on exact digital zero: tier 1 `channel` (had signal, then 3 s of peak 0.0), tier 2 `stream` (8+ physical channels entering tier 1 inside 2 s, shown as one alarm; a stereo pair counts as two), tier 3 `noSignal` (armed input still at zero 60 s in, a quiet notice). The audio thread makes one relaxed store per block (`TrackState::lastInputSignal`, the take frame after the last non-zero peak, on the peak it already computes, pre-fader so a muted strip is still watched). Everything else runs off the audio thread: `evaluateChannelAlarms` is called from `captureStatus` (so the 10 Hz timer) and from the daemon's `buildStatus`, and from the daemon's status loop even with no client attached, so a fault that comes and goes under a dead GUI is still latched. It is idempotent and any non-audio thread may call it. `alarmFrames` is its clock; `samplesSinceStart` cannot be, because pre-roll lands in it after capture goes live. Alarms never stop or alter a take and never make a stop look unclean. Recovery clears the live alarm; the report keeps start, end and name, and a continue carries them forward. `EngineStatus::channelAlarms` is additive: protocol stays 4.
- **Clock source.** `Source/Audio/ClockSource.{h,cpp}`. CoreAudio HAL C API, matched to the JUCE input device by name; two devices with that name read as "not available" rather than the wrong interface's clock. HAL calls can stall on a driver, so they run only through `clocksource::Probe`: its own thread, one read at a time, a bounded wait, and the thread owns only shared state. RECORD never waits for it: `goLive` requests a read and the report takes what is known at STOP. Pre-flight waits at most 250 ms. CoreAudio has no standard lock property, so never claim sync-lock status from this.
- Manual punch: while playback rolls, RECORD punches at the live playhead even if an older EDIT cursor exists; when stopped, an explicitly placed cursor is used, and a stopped playhead with no cursor APPENDS wherever it is parked (`manualRecordPunches`, `RecordPosition.h`, used by both RECORD and the header pill). A manual punch ends with one RECORD or STOP press; a normal live take keeps the two-press guard. Continuation at the end of a take is a separate part file, never a punch into the original.
- **A stopped cursor punch asks first (`MainComponent::cursorPunchNeedsAnswer`).** *Replace audio?*: Return is Record After Take, which clears the cursor and appends; Replace From Cursor punches; Esc cancels. Return must stay the safe answer. The answer is a fresh press through every refusal (`answerCursorPunch` calls `onRecordClicked` again) and does nothing if the transport moved while the question was open. A punch during playback and a selected range do not ask; a remote press is refused, so it never reaches the question.
- **Only a chosen range punches (2026-11-01).** The loop region is also the EDIT selection and RECORD's punch range. `SessionPlayer::selectRange` arms it; use it only for a gesture that sets both edges. `setLoopRegion` makes a region that loops and edits and never punches: restored ranges, half-made ranges and defaults. A selection punch calls `disarmRange` once it has started: one selection, one punch. The Loop button makes no region; loop-play with no region wraps the whole session (`SessionPlayer::activeLoopSpan`), and a loop already on stays inert while the seek lock holds. Never reintroduce an implicit region.
- **PUNCH mode has no arm state.** It punches the armed tracks at punch-in; there is no `punchArmed` and no arm snapshot, and nothing writes `armed` for a punch. `AudioEngine::setPunchModeOn` holds and restores loop-play, `clearSessionState` ends the mode, and `punchWindowTakeActive` marks the one take the window may end. Selection punches, PUNCH mode and remote refusal all key on `isRangeArmed`.
- **A remote RECORD never punches.** `handleRemoteTransport` sets `remoteStartInFlight` around `onRecordClicked` (desk macro, OSC and MCU all arrive there; the twin link has `twinStartInFlight`), and `runRecordPlan` refuses a punch from either. A remote PLAY is refused while PUNCH mode is on, because rolling into the range opens a punch.
- The punch writer adopts the existing take's container and bit depth on primary, backup and mirrors before stashing anything; mixed or unreadable existing media fails closed. Every copy needs a matching original before a punch, and all stashes complete before any writer opens. Originals stay as `.punchbase` until every spliced copy commits; surface rollback and save the session document/mix on stop.
- Never delete an existing `.punchbase` to start a new pass. Recover it before session playback/open, archive any partial replacement under `Session File Backups/Interrupted Punch*`, and refuse a new capture after a recovery until the restored take is reopened.
- Pre-roll applies to fresh takes only. **Lead-ins are deferred (2026-10-29):** a copy with less audio than the timeline position (a newly armed track in a punch/continue, or a backup/mirror added mid-session) never gets silence written at record start. `openTakeWriters` reserves part slots (`PendingLeadIn`, sized under the container ceiling), the pass's audio opens in the part after them, a marker goes to `<copy>/Audio Files/Pending Lead-ins/Track_NN.json`, and `completeLeadIns` fills the slots with silence during finalization from the real timeline start. `recoverInterruptedPunches` completes leftover markers (session open, record start). So such a track's take is `Track_NN` (silence) + `Track_NN_partKK` (audio): always read takes through `findTakeParts`/`ConcatReader`, never `Track_NN` alone. Selection punches capture only `[in, out)` in the audio callback, never from the UI timer; loop playback is suspended until teardown, and monitoring switches the armed track from old take to live input only during capture.
- **A punch take locks the playhead (2026-10-29).** `AudioEngine::startRecording` calls `SessionPlayer::setSeekLocked` when the take is a punch, and both stop paths clear it; meanwhile `setPositionSamples` and turning loop ON are no-ops for every caller (keys, cues, markers, EDIT/ruler clicks, MCU jog). The transport Loop button refuses during PUNCH mode or any take. Turning loop ON no longer makes a region. Position the playhead BEFORE opening a punch take (as `startSelectionPunch` does).
- **A punch splices where capture began.** The callback passes each block's playhead to `MultitrackRecorder::processBlock`; the first live block of a punch sets `punchCaptureOrigin` and the take clock base, and a new track's deferred lead-in is sized from it at STOP. Rolling manual punches and PUNCH-mode punch-ins are therefore not spliced early by the start work.
- **Punch and continue arms are exclusive and belong to one start.** Every refused start, in a recorder stage or an `AudioEngine::startRecording` guard, calls `discardTakeArms`, and every refusal sets `startError`.
- **A punch commits only if its capture is complete.** A primary overrun, FIFO gap or write failure during a punch rolls every copy back to the original. A hole in one copy leaves that copy on its pre-punch take, reported failed. Never let a splice install over a known hole and delete `.punchbase`.
- **Punch splice: the primary decides.** A backup/mirror copy that cannot splice keeps its pre-punch take and is reported failed; if the primary cannot splice, every copy rolls back. Unspliced punch audio is moved to `<copy>/Session File Backups/Unspliced Punch <time>/`, never deleted. A punch that captured nothing restores the take without a failure flag.
- **Every copy has its own thread and ring (`Source/Audio/CaptureCopy.h`).** The audio thread's path is unchanged: it pushes to the per-channel FIFOs. The one shard thread is now a distributor: it moves samples from the FIFOs to a ring per destination (primary, backup, each mirror) and never touches a disk. Each copy's thread does all of that copy's disk work: writes, part rolls, the 5 s header flush, closing. A writer is touched by one thread only; never add a call that flushes or writes another copy's file. A copy that falls a whole ring behind loses its oldest audio to silence, on that copy alone, stays sample-aligned, latches its failure flag and is named by `getCopyProblems()` (banner, `EngineStatus::copyProblems`, report `copyProblems`). Rings are per take, allocated untouched (`HeapBlock::malloc`), 2^18 frames at 48 kHz, cut down so all rings total at most 1 GiB, never under a second.
- **STOP waits for the primary as long as it takes, and for a copy only while it makes progress.** `finishCopies` abandons a copy with no progress for 30 s (`copyStallLimitMs`). An abandoned copy's thread, files, ring and flags live in shared state, so that thread can return from its write after the recorder is gone. The recorder never reads its `tracks` again and nothing touches its folder: no lead-in, splice, stamp, manifest or hash. It stays in `leftBehind`, and the next take leaves that destination out, by name, until its thread has ended, so RECORD cannot hang on a dead mount.
- **A copy also has a total limit: 60 s of draining from STOP.** The primary's punch install, lead-ins, stamps, manifest and hashes finish before any copy's, and each copy then finishes its own files on its own thread (`finishCopyFiles`, `CopyFinish`), so the primary never waits on a failing copy. Unbounded on purpose: a stalled primary (it decides the take), a copy's post-take work (no-progress limit only, because a healthy splice can run for minutes) and a copy's hash on a dead drive (the report stays `sha256Pending`).
- **Only the primary opens before go-live.** `openTakeWriters` gives every other copy a ring and a `CopyOpen`, which runs first on that copy's own thread (`CaptureCopy::openForTake`) and applies the same rules RECORD used to. A copy that fails one leaves the take by name (`CaptureCopy::leaveTake`); no copy can refuse RECORD. Nothing is ever written to a copy that fails identity. `VolumeProbe::answersWithin` is the one bounded check before RECORD, on the session's own drive.
- **From RECORD until the take's files are final (`AudioEngine::isTakeOnDisk`), no filesystem call on a destination's path runs on the message thread, on the audio path, or under the daemon's `commandLock`.** Readings come from `MultitrackRecorder::readDiskEstimate`, which loads atomics published by one `VolumeProbe` per destination. Gate an idle-only read behind `isTakeOnDisk`, or use `AudioEngine::hasSessionFolder` for "is there a session". `tools/invariants_audit.sh` checks the 10 Hz tick and `buildStatus`. Known exceptions: `adoptDaemonTakeSession` reading a rolling daemon take's documents on reattach, and completion handlers after a take's files are final. `juce::File::getVolumeSerialNumber` is always 0 on macOS: compare `f_fsid`.
- **Telemetry comes from the distributor.** `getDiskBytesPerSec` and `getRingFillPct` are published there because that thread never waits on a disk, so a stuck drive shows as falling throughput and a filling ring while it is stuck.
- **Pre-roll is written by each copy's own thread**, before that copy's first live sample. `goLive` sizes it (`preparePreRollDump`) and publishes `writersReady` at once. The ring holds live audio meanwhile, so a slow dump costs that copy alone.
- **AIFF keeps a current header.** `PcmAiffWriter` (in `FloatAiffWriter.h`) writes the same bytes as JUCE's integer AIFF writer and can rewrite its header while open. The periodic flush is header-only, like WAV's, with no fsync: every open file on every copy pays for it. `Source/Audio/AiffRepair.h` rewrites a header that is older than its audio from the real file size. It matches only bytes past the FORM with SSND last, and leaves every other file untouched. It runs first in `recoverInterruptedPunches`, so at session open and at record start for each copy.
- **FLAC length repair.** A crash leaves STREAMINFO's total at 0 and JUCE then decodes the whole file at every reader open. `Source/Audio/FlacRepair.h` reads the length from the last frame whose CRC-16 holds and patches those five bytes. It reads at most the last 1 MiB.
- **A punch keeps its position past a track's end.** `splicePunchFromReader` fills `[baseLen, punchIn)` with silence.
- **A spliced result may be several files.** A punch reads every part it wrote (`TakeStop::PunchFiles::fresh`) and writes to `Track_NN.punchtmp`, `.punchtmp02` and so on, under the container's ceiling, installed as `Track_NN`, `_part02`... Rollback moves every punch part out before any base part comes back, because a rolled punch part has the same name as a base part. In `recoverInterruptedPunches` a part with no sidecar is the punch's only if the punch's main file exists: it exists only after every base part has been moved aside.
- **Clips follow media after a crash.** The `.zfproj` holds `mediaLengths`. `AudioEngine::reconcileClipsWithMedia` runs after a session's playlists load and gives audio past those lengths a clip through STOP's own path (`seedDefaultClips (true, true)` from the saved lengths). An older project has no lengths, so only after a crash it measures from the end of the clips: a trim cannot be told from a lost pass otherwise. Recover saves before it deletes `recording.session`, because the marker is what asks for that.
- **The capture daemon pumps its CFRunLoop** (`CaptureMain.cpp`), never a bare sleep: JUCE's CoreAudio device-death and rate-change handling runs on timers.
- Tracks flagged `referenceMedia` in an older session are excluded from capture append length. Input detection uses input-only peaks. Device loss starts one finalization on the STOP worker. Stereo pairs cannot overlap. Saved stage routing survives reconnect. Delete confirmation reserves the session and rechecks capture.
- **Backup has its own format.** `AudioEngine::setBackupFormat` persists it as appProps `backupFormat`, default WAV 24; it returns false and persists nothing when the recorder refuses, and the Backup & Mirror Drives dialog commits nothing then. It reaches the daemon in `captureDaemonSettings`. Never change a capture default to suit a dialog.
- **The soundcheck report's band energies are why the recorder still has an FFT feed.** The callback fills `TrackState::fftSnapshot` and sets `fftBlockReady`; `ChannelStrip`'s 10 Hz timer releases it, and `SpectrumBands.h` reads the snapshot on that same thread, so a published snapshot stands still while it is read.
- Report and waveform scans: report hashing is serialized process-wide, yields 50 ms per 4 MiB and cancels superseded scans between reads; waveform scans run at background priority.

**Import and session state**
- Import goes into the active session's own `Audio Files`; with no active session, create a unique folder and seed fresh clips so stale edits cannot cross sessions. Pin the new session only after playable media exists; cancellation removes only files that import created. Sources with more than two channels split into one mono track per channel and roll back the whole source on failure.
- `seedDefaultClips` tracks prior source lengths, preserves pure end trims/renames/locks, and adds a clip for a continued take's new span without replacing the edited active take.
- Recording refuses timeline mutations from keyboard and toolbars. Daemon-mode EDIT uses fresh `EngineStatus` for position and coarse live peaks. LOCK gates the editor, reparented tools and remote transport as well as the mixer. Disk time comes from the recorder's per-volume estimate. Snap is Ctrl+4 because bare 4 recalls cue 4.
- Export inspects source channel counts before treating a linked pair as two mono files.
- **Range edits split EVERY clip crossing an edge** (`splitListAtTimeline`), so Clear/Ripple/Consolidate never leave an overlapping clip inside the range; Split and Separate split all overlapping clips too. Trims shrink fades proportionally to fit.
- **A clip carries its fade's full ramp (2026-10-29).** `fadeIn/OutSamples` stay the part inside the clip; `fadeIn/OutRampSamples` and `...RampOffsetSamples` (all 0 = an ordinary fade, bit-identical to before) describe a longer ramp cut by a split. Gain comes only from `clipFadeGain()` (`ClipModel.h`), shared by `SessionPlayer` and `mixWindow`; pieces are cut only with `clipSlice()` (split, crop); heal uses `joinedClip`. Editing a fade makes it ordinary; `sameClipList`, playlist JSON and the clipboard carry the ramp fields.
- QC takes only main take files, via `mainTakeTrackNumber` (`MultiPartReader.h`): exactly `Track_NN.<ext>`, never `_consolidated_K` renders or `.punchbase` sidecars.
- Channel-name CSV import (`ChannelCsv.h`) indexes by channel number ("3", "Ch 3", "Input 3"), keeps blank-name rows as gaps and detects 0-based lists. The handoff timeline CSV `[Tracks]` is `Index,Name,File,Channel,Part` with one row per file part.
- **New Session is guarded at the mutation.** All four paths (dialog, Welcome, CSV, console) go through `createSessionFolderStructure`, which refuses while recording or finalizing; `clearSessionState` and `resetAllStripState` also no-op under a take. A new session clears the undo history and retakes the mixer baseline on the next idle tick.
- Session ▸ Analysis (QC, song detection) refuses during a take or session job (`refuseAnalysisNow`) and stops by itself when a take starts during it; song markers go through `canMutateTimeline`. Crash recovery runs only after a daemon take is reattached and never lists the live daemon session; Recover deletes `recording.session` only after `openSessionFolder` succeeds and the session has saved.
- Every `*.zfproj` glob passes `ignoreHiddenFiles` (defence in depth: macOS's directory enumeration, which JUCE uses, already hides AppleDouble `._X` files, so the reported case did not reproduce).
- `setTrackLinkedRouting` refuses whole during a take (the input half is refused, so the output half must be too). The EDIT row combos call it on both sides, like MIXER and PATCH, so EDIT can't give a strip different input and output numbers, and its output combo is refused during a take. `setTrackArmed` tests the take state under the recorder's structure lock.
- **A pinned session is not a loaded session (2026-11-01).** `AudioEngine::activeSession` says which folder is current; `mixerSession` says which session the recorder's strips ARE. They differ at launch (the pin is restored from settings before anything loads), after a failed reopen, and while a daemon take is being adopted. `claimMixerFor (dir)` runs only after the mixer was loaded from `dir` or created for it: `openSessionFolder`, `createSessionFolderStructure`, a started take (`AudioEngine::startRecording`, `startDaemonTake`), `adoptDaemonTakeSession`, the first import into a new session, and Save As with no source. `clearSessionState` releases it. Never claim from a pin, and never make `setActiveSessionDir` or `AudioEngine::loadSession` claim: that would turn the guard off for exactly the paths it exists for.
- **`session_mix.json` is written only through `sessionmix::write` (`Source/Audio/SessionMixFile.h`).** It refuses a mixer that is not this session's and a zero-strip mix over a file that has strips. `writeSessionMetadata` applies the same guard to the whole snapshot, before any file is touched, because cues, takes and settings come from the same in-memory session; a patch carrying `setlist` or `playlists` counts even with no mix in it. Set `snapshot.mixerOwner`. The invariants gate refuses any other writer. `TrackFileTransaction` rollback restores its own journal copy and is not a mixer write.
- **Every refused save is visible.** `lastMetadataSaveError` carries the reason into STOP's message. Autosave skips an unloaded session on its normal interval and says so, with no 15-second retry, since waiting cannot help.
- **A take never joins a session that is pinned but not loaded.** `prepareRecordStart` will not continue into it and `makeNewSessionDir` gives a new folder, so RECORD still rolls and the unloaded session is untouched. A reorder refuses before renaming a take file, and an import refuses before writing one, because their indices would describe the wrong strips.
- **A daemon take's folder gets the mixer before it rolls** (`saveMixerToTakeFolder`), because a relaunch has nothing else to load. A failed write does not stop the take; the status line says so. On relaunch `adoptDaemonTakeSession` runs BEFORE `setExternalRecording (true)`, since strips cannot be resized under a take; `adoptRollingDaemonTake` owns that order, and the test drives this method, so a swap fails it. It is the session open without media: it must never touch the audio files or `recoverInterruptedPunches`, which belong to the rolling daemon. With nothing saved it sizes the strips from the daemon's status.
- **A saved session keeps at least one strip.** `reorderTracks` refuses to empty a session whose saved mix has strips, before any file moves. See the decisions.md entry.
- **Test engines that pin a session and then save must claim.** `host.engine.claimMixerFor (dir)` after `setActiveSessionDir`; otherwise the save is correctly refused.
- **Opening the open session is a no-op with a status line (`MainComponent::isSessionOpen`).** It compares canonical paths, so a link to the same folder counts. It holds in `openSessionFolder` itself, so File > Open, Welcome and Finder all get it. `openSessionFolder (dir, true)` is the only way to re-read: a recovered take and a restored backup changed the files. A session pinned but not loaded is not open, so it still opens.
- **A damaged session file is never silently replaced (`Source/Audio/SessionRepair.h`).** `openSessionFolder` calls `quarantineDamagedFiles` before anything loads: `session_mix.json`, `session_settings.json`, `markers.json` and the `.zfproj`. Each goes to `<name>.damaged-<date>` beside it, and `reportDamagedFiles` names the newest backup with a good copy. A mix with zero strips over a session with audio counts as damaged. Writers keep a copy too (`keepIfUnreadable`) for a file damaged after opening. The dated name deliberately does not end in `.zfproj` or `.json`, so no glob or load path picks it up.
- **`updateSettings` (`SettingsFile.h`) is the only shape of a settings write in UI code.** It reloads, applies, saves. The gate refuses a bare `saveIfNeeded` in `Source/UI`.
- **A missing session folder is a reported state (`sessionFolderIsMissing`).** The pin stays. Autosave says so, Save, Save As and Import refuse, and retries back off from 15 s to the autosave interval. Never let Save As or Import run with the folder gone: the copy would have no audio.
- **A session copy takes the session, not what happens to be in its folder.** Save As, Move and Show Handoff go through `copyDirectoryCancellable`. It skips a writer's staging file (`atomicfile::isStagingFile`: a hidden `.tmp` sibling, here only until its rename). A `WaveCache.wfm` that can't be read is dropped from the copy, because it can be rewritten during the copy and losing it costs a rescan (`wavecache::isCacheFile`). Any other file that can't be copied aborts the copy. The comparison in `ShowHandoff.h` skips the same files.
- **Save As, Move and Handoff go on when the source cannot be saved, by asking.** `offerContinueFromDisk`. Save As and Move then write the in-memory state into the new copy (`carryMixerInto`), the first place it can be saved. A handoff is verified against its source, so unsaved changes are not in it, and the prompt says so.
- **Remove Last Capture targets `AudioEngine::getLastCapture`.** Path plus `.zynforge-capture-id`, noted when a take really starts, never a folder date. It moves to the Trash, and a second press finds nothing rather than an older session. Test processes use `MainComponent::testTrashFolder`, never the real Trash. The recorder only cancels reports (`removeSessionAfterCancellingReports`) and takes the removal as a callback, so capture code knows nothing of settings or test modes.
- **No megabyte buffers on a thread's stack.** A worker's stack is 512 KiB on macOS. The gate refuses a `* 1024` stack array.
- **A RECORD press during an idle save is held, not refused (`releaseHeldRecordPress`).** For up to 5 s, and only for a metadata save. Jobs and a stop's finalization still refuse.
- **A session from an earlier build keeps its originals (`Source/Audio/SessionRemovedData.h`).** `removeddata::holdsData` decides whether a session's documents hold a value only a removed feature wrote. Keys alone mean nothing: earlier builds wrote them on every save, at their defaults. `removeddata::keepOriginals` copies the `.zfproj` files, `session_mix.json`, `session_settings.json` and `markers.json` to `Session File Backups/Before Feature Removal/`, through a staging folder and one rename, so the folder is complete or absent, and "once" rests on it existing. `keepRemovedFeatureData` runs it at both places a session's mixer enters memory, `openSessionFolder` and `adoptDaemonTakeSession`, before anything loads, and says so on the status line. It runs again in `writeSessionMetadata` and `sessionmix::write`, which refuse the write when it fails, so a failed copy can never be followed by a save that drops the data. Retention touches only folders named `<session>_<stamp>`, so this folder is never pruned, and `sessionrepair::newestBackupOf` never offers it. Audio is never touched.
- **Takes are data, not a feature.** The app no longer creates, switches, renames or deletes takes. The playlist model, `activeTake` and the `takes` JSON stay, because session files carry them and Punch, continue, undo, Crop, Ripple and export read them. Crop and Ripple still keep non-active takes in line. Tests make several takes through `Source/Tests/SavedTakes.h`.
- **`atomicfile::writeWith` checks the staged file's size.** `FileOutputStream::flush` discards the result of its last write, so a full disk left a short file and a clean status.

**Timeline edits (2026-11)**
- **Recording survives undo.** A clip undo step holds every track's playlist, and no take clears the stack. `playlistsToJson` records each track's `sourceLength`; `AudioEngine::restorePlaylistSnapshot`, the only thing undo and redo call, loads the snapshot and adds back what was recorded since, the way the take's own stop added it (`addRecordedSpan`; a plain default clip just grows). `loadPlaylistsFromJson` stays the session-open path. A ripple on some strips moves their takes and leaves markers and cue positions where the rest of the session still is; naming every strip (`namesEveryStrip`) moves the whole timeline. `timelineCutRefusal` refuses at the engine for a take, finalization, a session transition, or a locked clip that would have to move or go (any take). It is one undo step (`commitTimelineCut`, `TimelineCutAction`). A marker or cue added after the step survives its undo and redo at its own position (`keepAddedSince`): they are not on the undo stack, and a take's scene markers must not vanish with a Cmd+Z.

- **Marker types mean something.** `"user"` and `"song"` divide a show; `"split"`, `"range"` and `"scene"` mark a place and cut nothing in Export Songs. Old sessions' `Split` / `Range In` / `Range Out` read the same way by name. Scene markers cut only when a session has no other song markers. A split's marker is on its undo step (`MarkerDropAction`).

- **Master MUTE is monitoring.** Offline mix renders ignore it and follow the master fader. They follow solo, and `songexport::mixRenderWarning` says so; a silent mix says that too. `isAnySoloActive` counts strips.
- **Every export, bounce, consolidate and import writes through `CheckedFileStream`,** and checks its flag after the writer closes. A JUCE writer's destructor reports nothing and `FileOutputStream` ignores a short write of its last buffer, so only the closed file's size proves the end reached disk.
- **Sample-rate conversion is `SincResampler` (`Source/Audio/SincResampler.h`).** Same calls as `juce::ResamplingAudioSource`, which is no longer used. The output starts on the source's first sample.
- `TrackExporter::sizeRefusal` runs before a file opens; add any new format limit there.
- Heal Separation at the playhead reaches 250 ms (`kHealReachSeconds`).
- `activeTake` from a file is clamped into the takes on load.

**Daemon, remote and verification**
- Daemon status freshness is the receive time of the last actual status push; UI timer repolls never renew it. A lost link invalidates the snapshot and keeps an *unknown rolling capture* guard rather than reporting healthy local idle; that guard ends by `resolveLostDaemon`, never by time. `AudioEngine::captureStatus()` returns the cached daemon `EngineStatus` (with `source` and `statusAgeMs`) when external capture is active.
- **A lost daemon is a state, not a dead end.** `resolveLostDaemon` tries to attach (`CaptureSupervisor::reattach`, which never launches): `back` adopts whatever the next fresh status says, `gone` (nothing listening) proves no take is rolling and ends it through `endDaemonTake`, `unknown` (something holds the port and fails the handshake) keeps the guard. The timer retries with backoff. A take is called over only by a daemon that answers or by `gone`. Quit and turning daemon mode off work from `unknown` by asking and saying nothing was stopped (`leaveLostDaemon`). They never kill a daemon. Session ▸ Recording & Sync ▸ Reconnect Capture Daemon (975) and a RECORD press do the same, and only they may launch one, only after `gone`.
- **A daemon take ending any way reaches `endDaemonTake`:** STOP's reply, a status that says it ended (`daemonTakeAdopted`, device loss in the daemon, a reply that never came), or `gone`. It loads the media on the STOP worker (`AudioEngine::finishExternalTakeAsync`) and saves metadata. A status saying a take is rolling that this window has not adopted is adopted the same way (`adoptRollingDaemonTake`, which also swaps in that session's mixer; the swap refuses under a rolling take, which is what lets a reattach in the same window leave the mixer alone, so it must run before `beginExternalTake`).
- **Daemon STOP never blocks the message thread.** `CaptureSupervisor::stopRecordingAsync` owns the thread. `captureMetadataPending` is up until the reply, so a status that arrives first starts no second follow-up, and the bound is 10 minutes, for a daemon gone silent. `stopActiveCapture` no longer has a daemon branch.
- **RECORD with no answer is not a failure.** `requestDaemonTake` keeps the guard and button `REC ?` until a fresh status settles it. A status from before the daemon reached the START proves nothing, so only 10 s of "not recording" gives up. A daemon refusal keeps its reason.
- **`AudioEngine::beginExternalTake` makes the daemon's folder this engine's session**, for markers above all, on start and on reattach.
- **Clips in memory belong to the folder they came from.** A daemon RECORD opens a new folder, so its finish reseeds rather than preserves (`CaptureStopJob::sameSession`).
- A daemon START while recording is refused before `armContinue` or any recorder failure latch changes. Status socket writes never hold `commandLock` across a blocking send. Daemon callback loss finalizes the rolling take and latches `captureDeviceLost` in status (and in `session.report.json`) until the next successful start; verification and show handoff require review of it.
- **Remote control lives in `RemoteControl` (`Source/Network/RemoteControl.h`, 2026-10-29)**: the console OSC listener with its debug log and channel-name capture, the desk macro listener and the MIDI control surface. `AudioEngine` owns exactly one, BY VALUE (`remotes`), so their lifetime stays nested inside the engine's; callers reach them through `engine.getRemotes()`. Never make it a `unique_ptr`: the OSC thread calls back through `engine.getRemotes()`, and a `unique_ptr` is already reset while its object is being destroyed. The invariants gate checks both. The audio thread touches nothing in it. Remote TRANSPORT still goes through `AudioEngine::performRemoteTransport`.
- Remote RECORD/STOP (local or daemon) route through `MainComponent` preflight and the two-tap STOP guard; a first remote STOP is refused with an explicit "armed" response. Without a host handler, `AudioEngine::performRemoteTransport` refuses record/stop and the standalone `TransportBar` cannot start or end a take — never reintroduce a direct timestamped-session fallback.
- On continuation, `session.report.json` lists every on-disk part, accumulates prior capture warnings and counters, records `mirrorsSkipped`, and flags a failed final hash; the local UI surfaces an asynchronous report failure. `Session File Backups/reorder_*` journals are never pruned by snapshot retention.
- `Source/Audio/ShowHandoff.h` hashes every copied file against its source, writes channel-map/timeline sidecars and a manifest, and flags incomplete capture evidence. It does not verify external backup drives or certify show readiness. It runs on the owned, cancellable export worker, holds `sessionIoBusy`/transition ownership, refuses nonempty destinations, and leaves `HANDOFF INCOMPLETE.txt` after interruption — never clear that marker before the copy finishes.
- `tools/verify_take.sh` rejects gapped parts, short reported frame totals, pending/failed hashes, capture warnings and unlisted files.
- The header lays out fixed controls before the optional MIDI/Dante pills, reserving room for status and the sample-rate alarm; the window cannot shrink below that width.

## Critical universal rules

### std::sort comparators must be a STRICT WEAK ORDERING
- The hardened `std::sort` (newer Xcode/libc++) **aborts (SIGABRT)** when the comparator isn't a strict weak ordering — a real crash, not a warning. The classic trap: reversing a sort with `return forwards ? lt : ! lt;`. `! lt` reports *equal* elements as each `< ` the other (and `cmp(a,a) == true`), which is invalid. **Reverse by swapping the operands**, never by negating: build the comparison from `rows[forwards ? a : b]` vs `rows[forwards ? b : a]`. Also map non-finite floats (NaN) to a floor so the key is total. The sortable table dialogs (`SessionRecoveryDialog`, `QcReportDialog`) both follow this; copy that pattern in any new one. This crashed the app on relaunch-after-crash (the recovery dialog) — `SessionRecoverySortTests` guards it.

### Don't block the message thread (2026-08-11)

The message thread runs the 10 Hz timer that services punch, the transport labels, the meters and the menu state. Blocking it for seconds is indistinguishable from a hang to an engineer mid-show, so **unbounded file or subprocess work belongs on a thread**:

- **Owned + joined, never detached — and only through `sessionJobs`.** Every unbounded session-file job (track export, stem/mix bounce, import, Save As copy, relocation, show handoff) runs on `MainComponent::sessionJobs` (`Source/UI/SessionJobRunner.h`): `reserve()` the session-I/O reservation, `release()` it on any pre-launch exit (chooser cancelled, validation failed), then `launch (work)`. The work runs on the owned thread with a cancel flag and **returns** its completion; the runner clears `sessionIoBusy` on the message thread *before* the completion runs, on every path — a cancelled job that returns `{}`, or one that throws. Never write a raw `std::thread` in `Source/UI` or release `sessionIoBusy` from a worker: eight hand-written launches each owned their own release, and the track export's cancel path skipped it, so a quit-cancel left every session operation refusing until restart. The destructor's `sessionJobs.cancelAndJoin()` keeps jobs from outliving the engine. Metadata saves share `sessionIoBusy` through their own `pendingMetadataSaves` count; `enqueueMetadataSnapshot` refuses while a job holds it, so the two owners never overlap. Gate: *session jobs release their reservation structurally*.
- **Resolve engine state on the message thread, then hand plain values to the worker.** `startExportTracksTo` builds its job list (source files, dest stems, stereo flags — all reads of TrackStates) up front, then the worker touches nothing but `juce::File`s; the stem bounce likewise resolves each stem's name/layout before launch. Report back through the returned completion with a `SafePointer`.
- **A UI worker never holds `recorder.getStructureLock()` across a render.** The 10 Hz timer calls `engine.captureStatus()`, which takes that lock, so a bounce that held it for the whole render froze the entire app until the last window was written. `forEachStereoMixWindow` snapshots every strip it reads (fader, pan, solo and mute gate) under a brief lock of its own and renders lock-free; the file is the mix as it stood when the bounce began. Gate: *UI workers never hold the structure lock across a render*.
- **Timeline mutations go through `MainComponent::canMutateTimeline (action)`.** It refuses — with the reason on the status line — while capturing (local or daemon), while `sessionIoBusy`, and while LOCKed. Keys, menus and editor enablement gate these too, but every clip/range/marker/undo function checks here instead of repeating a partial `isRecording()` guard (18 copies did, and none checked LOCK or session I/O).
- **`juce::ChildProcess::readAllProcessOutput()` has NO timeout** — it loops on a blocking pipe read until the child closes it. `waitForProcessToFinish(ms)` placed *after* it is dead code. Wait first (then `kill()` on timeout), and put the whole call on a background thread if the child can hang (`MultitrackRecorder::querySmartStatus` does both; `MainComponent::pollSmartStatusAsync` keeps one probe in flight).
- **Never write to the session volume while a take is rolling.** `preflight::measureWriteSpeedMBps` writes 16 MB; the pre-flight checklist now reports the requirement only when `isRecording()`.
- **Report scans run on `analysisJobs`, not `sessionJobs`.** Same runner class, its own flag and no session reservation, because RECORD must never wait for a read-only scan. The 10 Hz timer cancels a scan when a take starts, a stopped scan writes no report, and a result is delivered only through `analysisResultWanted`. Never open a modal from a scan without it.
- **Device loss finalizes on the STOP worker.** `audioDeviceStopped` runs on the message thread under JUCE's audio lock, so it starts `launchCaptureStopJob` and returns. The engine then reports `onTakeInterrupted`, because no STOP press reset the transport or saved the session.
- **A bad copy does not stop the show.** `claimCopy` separates `conflict` (someone else's audio: the take is refused, as before) from `unwritable` (full or read-only: the copy is left out and named).

### Real-time discipline (audio thread)

- The audio callback never allocates, locks, opens files, calls `Logger`, or touches the message thread.
- **`MultitrackRecorder::getTrack(i)` is NOT bounds-checked in release** (it's `*tracks[i]`, called once per strip per block). Every caller range-checks against `getNumTracks()` first; a debug `jassert` catches the ones that don't. **Never bound a loop that dereferences a TrackState on `player.getNumTracks()`** — the player's count comes from files on disk and can exceed the mixer's strip count (delete a strip after recording). That mismatch is what indexed off the end of the vector in the stereo-mix bounce; the mixer is authoritative for anything that reads mixer state. `jmax(recorder, player)` is fine purely as a *range check* on an index, which is how the other `AudioEngineClips` entry points use it.
- **The mix rules have ONE definition: `Source/Audio/MixKernel.h` (2026-10-29).** The solo and mute gate (`mix::audible`), `mix::streamAudible`, the fader floor (`mix::stripDb`), Trim-Follow, the constant-power pan law, the master output pair, the mix bus hold-off rule and master gain are called by BOTH the audio callback and the offline stereo bounce. There is no stereo-pair rule: each half of a pair has its own fader, pan and mute, and the views and setters keep them in step. Never re-derive one inline: the invariants gate refuses a pan law, solo gate, fader floor or master gain formula in `AudioEngine.cpp` / `AudioEngineClips.cpp`, and AudioCallbackTests' "Live playback and the offline bounce mix the same session identically" compares the two outputs sample for sample, on fader, pan, stereo pair, mute, solo and master. Deliberate differences, not drift: the bounce has no live input, no trim-follow and no mono-master fold-down, and it ignores master MUTE.
- State transitions happen via `std::atomic` flags. Writers + readers are constructed / destroyed only on the message or background threads.
- **No thread is killed (2026-11-01).** JUCE kills a thread that outlives a `stopThread` timeout (`0` kills at once), locks held and writes half done, and `~TimeSliceThread` does this after 2 s, `juce::ThreadPool` after 500 ms. So every `stopThread` in `Source` takes `-1`, every `juce::TimeSliceThread` is stopped explicitly before its destructor runs (recorder writers, player reader, mix writer, EDIT scan threads), and a job that needs a worker uses `Source/UI/SerialWorker.h`, not a `ThreadPool`. The gate *no thread can be killed by force* enforces it. The trade-off is deliberate: a thread stuck on a dead drive makes quit wait rather than crash.
- Scratch buffers (`outputAccum`, `playerScratch`) pre-allocate in `audioDeviceAboutToStart`.
- Master mute is enforced at the device boundary for the selected master output pair. Per-strip and stream routes are accumulated before the master bus and may share those channels; never implement mute by zeroing only the stereo master sum. Other direct/FOH outputs stay independent.
- **`TrackState` lifetime is shared (2026-10-29).** `MultitrackRecorder` owns tracks through `shared_ptr` and `TrackState` derives from `enable_shared_from_this`. Every UI surface that caches a `TrackState&` (`ChannelStrip`, `LedMeter`) also holds `std::shared_ptr<TrackState> keepAlive`, taken in its constructor with `s.weak_from_this().lock()`, so a track the recorder drops -- `setStripCount` shrink, delete, session open/close, or a device restart that reshapes the set in `MultitrackRecorder::prepare()` -- stays valid until that surface is rebuilt. This closes the use-after-free class that four audits re-fixed one call site at a time; ASan reports it if a keep-alive is removed (*Strip lifetime* suite). The audio thread only dereferences the recorder's pointers and never copies one, so no reference-count traffic or deallocation happens there. Gate rule 1 requires the keep-alive on any new caching surface. **`condemnAllStrips()` is still called before frees** so detached surfaces stop their timers at once instead of showing a stale meter for a tick, and it must still reach all three views (gate rule 2), but correctness no longer depends on remembering it at every free. Any layout change bumps `getTrackGeneration()` -- add/remove, stereo link/unlink, and `reorderTracks` -- and both views rebuild on a generation change; `EditPage::refresh()` additionally compares the logical layout. Original rule, kept for history: **Any path that FREES `TrackState`s (shrinks the recorder vector) must call `condemnAllStrips()` FIRST.** A `ChannelStrip` holds a `TrackState&` and its meter/strip timers keep sampling `state.peak/armed/...` on the 10 Hz clock until `rebuildStrips()` runs on the *next* tick — so `setStripCount` to a smaller count, `setStripCount(0)`, or `resetAllStripState()` under live strips opens a ~100 ms freed-heap read window. `condemnAllStrips()` stops every strip's timers (via `invalidate()`) before the free; it's idempotent and a no-op on an empty vector, and each caller sets `lastTrackCount = -1` to force the rebuild. **It covers BOTH views.** The EDIT rows have the identical hazard — each `EditPage::TrackRow` owns a `LedMeter` holding a `TrackState&` on its own timer, and the rows rebuild only on EditPage's next 24 Hz tick — so `condemnAllStrips()` also calls `editPage->condemnAllRows()` → `TrackRow::invalidate()`. Fixing this on the MIXER alone (three times) left EDIT reading freed memory the whole time; when you add a surface that caches a `TrackState&`, wire it into `condemnAllStrips()` in the same change. Callers that must condemn: bulk strip delete, session open (`openSessionFolder`)/close, console-session build, **and every "new/blank session" path** (`launchNewSessionDialog`, `applySessionTemplate`, `createSessionFromCsv`, `showStartupWelcome`). Growth-only `setStripCount` (import, AddTracks) frees nothing and needs no condemn. This UAF class was closed incrementally and kept leaving missed sites — grep every `setStripCount`/`resetAllStripState` caller when touching this.
- **Hero panels over the flat `bgDeep` body are `setOpaque(true)`** (`BigClockPanel`, `PerfDashboard`) — they `fillAll(bgDeep)` first so the look is unchanged. A non-opaque panel that repaints on a timer forces `MainComponent::paint` to redraw the slice behind it every tick; keep timer-driven panels opaque. Idle CPU itself is dominated by the CoreAudio device callback + the per-strip meter/UI-timer swarm, not these panels — see `decisions.md` *Idle CPU left at ~5%…*.
- **Live recording waveform** is built on the audio thread: `TrackState::liveWavePush` bins captured input into min/max pairs and pushes them through a pre-allocated lock-free `AbstractFifo` (`liveFifo`); the EDIT timer drains it (`liveWaveDrain`) and draws. Keep it allocation-free + lock-free on the push side — never grow the ring, log, or block there. Reset via `liveWaveReset()` on record start (message thread). This is why the live waveform is detailed + final-on-stop (no post-stop re-scan), like Reaper/Pro Tools.
  - **The live envelope OWNS the lane while capturing — even over clip blocks.** In `EditTrackRow::paint`, `showLive` (`liveRecording || liveHold`) takes precedence over `haveClipBlocks`: the continuous live path draws when `! haveClipBlocks || showLive`, and the static clip-block renderer is skipped while `showLive`. This is essential for a **continue** — every stop seeds a default clip over the take, so a continued take has `haveClipBlocks == true`; without the override the growing capture would be hidden behind the static clips until the post-stop re-scan. The existing take draws dim (`drawContinueExisting`, `[0, base)`), the new audio grows hot on top (`drawRecEnvelope`), then the clips take back over on stop. Don't gate the live envelope behind `! haveClipBlocks` alone.
  - **The live envelope is placed by TIMELINE FRACTION, not stretched to the lane.** `recPeakL` covers `[0, recPos]` (`recPos = recPeakL.size() * kLiveBinSamples`); the lane covers `[0, total] = max(playerTotal, recPos)`. `EditTrackRow::paint` confines `drawRecEnvelope` to `liveFrac = recPos/total` of the lane and draws the dim existing take across `existingFrac = playerTotal/total`. For a **continue** these collapse to the old behaviour (`liveFrac == 1`, take is the `[0, takeEnd)` prefix). For a **punch** `total` is the full take so `liveFrac < 1` and the capture sits AT the punch point (with the whole take dim under it) — **don't** draw the envelope across the full lane width or a punch looks like it records at the END. The silent prefill columns in `recPeakL` encode the offset within that confined slice.
  - **`EditTrackRow::paint` ALWAYS paints the pinned header last, in both lane VIEW modes (Waveform, Markers).** The lane-content drawing runs inside a `drawLane` lambda so a non-waveform mode can early-`return` from the *lambda* without skipping `paintHeader(...)` below. A mode that returned straight out of `paint()` would skip the header, so with the timeline scrolled its content would draw over the pinned name + I/O combos (the header is normally redrawn on top to cover lane content under the pinned-left region). Don't add a lane mode that returns from `paint()` directly; return from `drawLane` (or fall through) so the header still paints.
  - **The EDIT ruler MUST track the wave's horizontal scroll (2026-06-16).** `EditTimeRuler` is a FIXED-width sibling drawn ABOVE the wave lanes — it does **not** live inside the scrolling `viewport` — so it subtracts `viewport.getViewPositionX()` from its time→x map (`rulerTimeToX` − `scrollOffsetX`; the inverse `rulerXToTime` + it, so marker hit-test stays right). `EditPage` pushes the offset via `viewport.onScroll` (which `ScrollViewport::visibleAreaChanged` fires for manual **and** programmatic/auto-scroll + zoom-to-selection) and again in `resized()`. Omit it and every tick / label / playhead / edit-cursor / marker drifts right of the audio by exactly the scroll amount once zoomed in — the recurring **"ruler bug."** The ruler's `pxPerSec` maps across the full `contentW` (same as the lanes); only the origin shifts. Locked by `EditRulerScrollTests`: the ruler playhead must equal the lane's `headerW + (int)(frac*(waveW−8)) + 4 − scrollX`.
  - **Live-draw arming is SELF-DRIVEN per row, every tick — never a one-shot.** `TrackList::pushRecLevels` (EDIT timer) calls `row->setLiveRecording(true, prefill)` for each **armed** row every tick before draining, deriving the live state from the current recording+armed state (`setLiveRecording` only resets on the off→on edge, so it's idempotent). Do **not** re-introduce a one-shot "record just started" arm: if that single edge is missed or clobbered by a refresh between ticks, `appendLivePeak` early-returns on `! liveRecording` and silently discards every drained peak for the rest of the take (the live waveform never builds — this was the long-standing "continue doesn't show the waveform" bug). Arm **only armed rows** — a blanket arm of every row put non-armed lanes into an empty live state and blanked their existing waveforms. `prefill = recordBaseSamples / kLiveBinSamples` anchors the continue's new audio after the existing take. `LiveWaveContinueTests` locks the recorder-side data path (a continue emits live-overview columns like a fresh take).
- **A take is a SEQUENCE OF FILES.** `Track_NN.<ext>` + `Track_NN_partXX` continuations (auto-split past the container cap, or **continue-recording** via `armContinue` → `nextContinuationPart`) are stitched into one seamless take by `ConcatReader` (`Source/Audio/MultiPartReader.h`) on playback (`SessionPlayer`), the EDIT thumbnail (`thumbnail.setReader`), **and File ▸ Export** (`TrackExporter` calls `ConcatReader::create` — an export used to silently contain only part 1). Any code that reads a whole take must stitch its parts; matching `Track_NN.<ext>` alone drops every continuation. **Continue/append never modifies an existing file** — it only adds a new finalised part, so it can't corrupt what's captured. Prefer this (a new part) over rewriting a file. The splice below is now only for a mid-take punch.
  - **Takes are not always WAV.** Session load (`SessionPlayer`), QC and **the timeline CSV** glob every supported container (`.wav/.flac/.aif/.aiff`), not just `.wav`. Filter by extension; parse the track index from the `Track_NN` **prefix**, not the last `_` (which turned `Track_04_part02` into `part02` → dropped). A `Track_NN*` glob also matches `Track_NN.punchbase.<ext>` — **explicitly skip `.punchbase`** (`takeIsMultiPart` and `swapTracks` both did not, despite comments claiming otherwise).
  - **A CONTINUE extends the take in ITS container, not the current capture format.** `startRecording`'s continue scan resolves the existing take's container + bit depth off disk and adopts it. Looking only for the *current* format's extension meant that changing format between takes found nothing: `recordBaseSamples` stayed 0 and the "continuation" was written as `Track_NN.flac` part 1 next to the existing `Track_NN.wav` — two files claiming one track index. Locked by *Continue-record adopts the existing take's container*.
  - **The recorder's failover keys on `WriterChannel::active`, NOT `writer != nullptr`.** A failed primary writer nulls `writer`, which is indistinguishable from a deliberately-empty stereo-R slot; keying the drain on `writer` skipped the whole channel (backup + mirrors + FIFO) after a primary failure. `active` is set when any destination opens at record start; a participating channel keeps draining even with a dead primary so backup/mirrors keep rolling. See the audit ADR in `decisions.md`.
- **STOP parks the transport at the take's END, not 0 (live-recorder convention).** `AudioEngine::stopRecording` **fails closed when not recording** (a stray OSC/console transport-stop while idle or playing back would otherwise run the whole tail — reload the last session, reseed clips, yank the playhead — and wipe edits). When recording, it captures `recorder.getRecordTimelineSamples()` **before** `recorder.stopRecording()` (which zeroes the recorder's base offset), then after `player.loadSession` — which rewinds to 0 — restores the playhead there with `player.setPositionSamples(...)`. This is deliberate and the opposite of a DAW (Reaper's Stop snaps the edit cursor back to the pass start): the next RECORD from that stopped playhead takes the **append-a-new-part** branch (`MainComponent::planRecordPosition`, `continueAppend`), so continue resumes seamlessly. Don't "helpfully" rewind to 0 on stop.
  - **Same-session reloads PRESERVE clip edits; only a genuine session OPEN wipes them.** `seedDefaultClips(preserveEdits)` and `AudioEngine::loadSession(dir, preserveEdits=false)` are the knob: `stopRecording` and `swapTracks` pass `true` (keep every edited track's splits/fades/takes, reseed only plain defaults); the real open funnel passes `false` because its `.zfproj` playlist restore repopulates. `swapTracks` swaps the engine's clip lists + take playlists for the two indices rather than reloading through the wiping path. This closed a data-loss blocker (record-stop / reorder / OSC-stop silently wiped every edit). Locked by *swapTracks preserves clip edits* in `RecordingIntegrityTests`. **`swapTracks` renames ALL of each take's on-disk files — the main `Track_NN.<ext>` AND its `_partXX` continuations, across every container (`.wav/.flac/.aif/.aiff`) — via collision-safe temp staging.** Renaming only `Track_NN.wav` (the old behaviour) stranded a continued or FLAC/AIFF take's parts at the old index, so a reorder permanently stitched them onto the wrong channel; locked by *swapTracks renames continuation parts*.
    - **The "edited" test (`isPlainDefault`) must NOT compare clip length to file length.** A continue-record / length-changing punch GROWS the file, so an unedited default clip left at the old length would be misclassified "edited" and preserved SHORT — silencing the appended audio (a real regression, caught by a re-audit and locked by *Continue-record grows the take* in `RecordingIntegrityTests`). A plain full-from-zero single clip (no split/fade/gain/mute/move/cross-track-file) is always refreshable to the current length; only those shape edits, or >1 clip / >1 take, count as "edited". A pure END-trim reloaded in place is refreshed back to full — audio is never lost, which is the correct trade for a recorder.
  - **Record-safety guards live at the ENGINE, not just the UI buttons.** `startPlayback` refuses while recording, `stopRecording` fails closed when not recording, `setTrackStereo` refuses while recording. Network/remote entry points (OSC, MCU, timecode chase) reach the engine directly and bypassed the UI guards. Add new transport/layout entry points at the engine level or they'll be reachable from the network unguarded.
- **Punch-in is OFFLINE, never a real-time write into a take.** A punch records a clean fresh `Track_NN` from 0 like any take; the existing copies — **and all their continuation parts** — are moved to `.punchbase` sidecars in `startRecording` (before the writer truncates) and spliced back in `stopRecording` via `Source/Audio/PunchSplice.h` (`base[0,punchIn)+fresh+base[after]`, temp + atomic swap, all copies). The splice sits **after `closeWriters()` but before the async SHA thread** so the report's SHA/length describe the spliced files. Keep it there — never push punch writes onto the audio thread, and never overwrite a take in place (a failure must revert to the untouched base). **Multi-part bases ARE supported** (a take built up by continue-recording): `splicePunchParts` reads the whole take (all stashed part sidecars) via `ConcatReader` and **flattens** it into one spliced `Track_NN` (the parts are deleted on success, restored on failure). So you can punch anywhere on any take, single-file or split. `armPunchIn` sets `recordBaseSamples = punchInPos` so the clock / playhead / live-capture waveform anchor AT the punch point (the new audio builds there, existing take dim underneath) — same machinery as a continue. The punch point is the EDIT cursor (set by a wave-pane click, `EditTrackRow::mouseDown`) or the rolling playhead; a stopped playhead never punches. See the punch ADR + *Read-only offline DSP is allowed…* in `decisions.md`.

- **`tools/invariants_audit.sh` is the CORRECTNESS gate** — a second CI step next to the design audit, enforcing the bug CLASSES that five audit passes each found re-violated somewhere new. **34 checks**, must stay CLEAN. The earliest are summarized here; `tools/invariants_audit.sh` defines the full current set: (1+2) every consumer of a cached `TrackState&` exposes a detach hook **and** is wired into `condemnAllStrips()`; (3) no `getTrack()` bounded by a player-derived count; (4) `TrackState::name` written only via `setNameThreadSafe`; (5) no `.wav`-only `Track_*` globs; (6) bare `Track_*` globs exclude `.punchbase` sidecars; (7) the sessions root resolved only via `AudioEngine::getSessionsRoot()`; (8) no bare `reload()` on the shared `.settings`; (9) **device reconfiguration is guarded against a live take**; (10) **`Theme/` paints accents via `brand::onSignal`, never a hardcoded `Colours::white`/`black`** (only `BrandColors.h`, home of `gloss()`/`onSignal()`, may name them); (11) **a `std::thread` join is never skipped by an early flag return** -- destroying a joinable thread calls `std::terminate()`, and a reader that clears its OWN run flag turns `if (! running.exchange(false)) return;` into a process abort (a Yamaha/A&H desk dropping its link killed the app on the next Connect or quit; the rule found two more sites written the same way the moment it existed). Rule 10 exists because the DESIGN gate **excludes `Theme/`** -- which is how `drawToggleButton` shipped a hardcoded white letter over every caller's accent: right for record red, ~1.2:1 on solo yellow. An exclusion added so a gate can express a rule becomes the one place the rule isn't enforced; a LookAndFeel paints for every call site, so it's the most expensive place in the codebase to hardcode a colour. **When you add a rule, verify it goes RED against an injected regression before landing it** — two of the original seven were blind (a commented-out call, and an unrelated comment in the same file, both satisfied the check); the rules strip comments (`sed 's,//.*,,'`) before grepping for exactly that reason. Every rule enumerates over the **consumers** of a hazardous pattern, not the call sites that trigger it — that's what makes it find instances reading missed. Rule 9 did so the day it landed: `setAudioDeviceSetup()` / `initialise()` RESTART the device, and `AudioEngine::audioDeviceStopped` -> `recorder.release()` -> `stopRecording()`, so ANY caller that reconfigures the device mid-take silently ENDS it. The guard existed in `applySessionSettings` and nowhere else; adding the rule immediately surfaced three more unguarded sites (the DEVICE panel's three combo handlers, `applySessionSampleRate`, and both new-session device pushes). **Guard at the MUTATION, not at the dialog launch** — the DEVICE panel is non-modal and can already be open when RECORD is pressed. Hooks aren't tracked by git: run `tools/install_hooks.sh` once per clone to get both gates pre-commit.
- `tools/design_audit.sh` is the CI gate (pre-commit hook) enforcing all of the above — **7 rules**, must stay CLEAN. Scope = `Source/{UI,Audio,Network,Capture}`, excludes `Theme/` + `Tests/`. The rules: (1) no raw `juce::Colour(0x..)`/`fromRGB`; (2) no bare `Colours::white`/`black`; (3) no raw `juce::Font`/`FontOptions`; (4) **withAlpha opacities must be `brand::alpha::` tokens — raw floats now FAIL** (stricter since the catalogue retirement); (5) rounded-rect radii are `brand::radius::` tokens (≤2px micro exempt); (6) no raw `.brighter()`/`.darker()` (use `brand::lift`/`sink`); (7) **spacing ratchet** — raw-int `reduced(N)` count must not grow past `SPACE_CEIL` (new spacing must use `brand::space::`; lower the ceiling as the tail migrates).

### Redundancy: a mirror must be provably somewhere else

- **A mirror writes `root/<sessionName>/Audio Files/Track_NN.<ext>` -- the SAME shape as the primary and backup.** So a root that is the session's PARENT resolves onto the take's own files: two `AudioFormatWriter`s, one path, for the whole show. With the picker opening at `~/Music` and sessions under `~/Music/Zynforge Sessions`, that was one click away. **`MultitrackRecorder::mirrorRootRejection` is the rule** (holds the session / inside the session / duplicates another mirror / is the backup root) and it runs in TWO places: the picker, for the message, and **record start, for the safety** -- a mirror config is persisted and outlives the dialog, and the *session* moves, so a root that was fine when configured becomes the session's parent the moment a session is opened from that folder. Validating only in the dialog is the same mistake as guarding a dialog's launch instead of its mutation.
- **A mirror that never OPENS creates no `Mirror` entry, so `anyMirrorFailed()` cannot see it.** Collisions and unreachable drives are counted into `getMirrorsSkippedAtStart()` and the recording banner reports them -- otherwise the engineer runs a whole show believing they have a copy they don't. `WriterChannel::mirrors` is built from `activeMirrors` (the filtered list), so **anything indexing a mirror by position must index `activeMirrors`, not `mirrorConfigs`** -- the session report did, and a single skipped mirror would have shifted every later root by one.
- **Writer failure state outlives the writer object.** Backup/mirror open and runtime failures are take-level latches; clearing failed writers at stop must not make status/reporting healthy again. `backupActive` means a requested backup is actually ready and has not failed, not merely that a path string exists.
- **An engine setter that can REFUSE must report the refusal, and the caller must not persist what was refused.** `MultitrackRecorder::setMirrors` returns false mid-take; `AudioEngine::setMirrors` is `[[nodiscard]]` and writes nothing when it does. Persisting a refused change made the settings file claim a redundancy the live recorder wasn't providing, and a restart made it look like a flake rather than a rule.

### Network + remote entry points

- **Every inbound OSC socket uses `OscPacketReceiver` (`Source/Network/OscPacketReceiver.h`, 2026-10-29), never `juce::OSCReceiver`.** JUCE's parser recursed on nested `#bundle`s with no depth cap: one ~64 KB datagram from any LAN host overflowed the listener thread's stack. `oscwire::parsePacket` is bounds-checked, caps nesting at 8, and rejects bad sizes, truncation and trailing bytes; delivery stays on the message thread through the same Listener interface. A gate rule refuses `juce::OSCReceiver` as a type. JSON from a socket has its own rule, below. Console trim (`setTrackLiveInputGain`) drops non-finite values and clamps to -96..+72 dB; X32 head-amp wire values clamp to 0..1.
- **Remote surfaces do NOT touch `TrackState` directly.** `AudioEngine::setTrackMuted/Soloed/Armed` (and the `toggle*` variants) are the only sanctioned path for OSC and MCU. They do two things a caller keeps forgetting: **mirror the stereo pair** (the invariant lived only in `ChannelStrip::pairState`, so every non-UI surface half-updated a pair) and **hold `MultitrackRecorder::getStructureLock()`** across the range-check-then-use.
- **`condemnAllStrips()` does not protect network threads.** It detaches COMPONENTS. A worker thread that range-checks `getNumTracks()` and then calls `getTrack()` is a TOCTOU against `removeLastTrack()` freeing the `TrackState` -- `captureStatus()` walked the whole vector that way. Every structural change to `tracks` and every off-audio-thread read now take `structureLock` (recursive, so nesting from the message thread is fine). **The audio thread does not take it** and is unchanged by this.
- **A subscription EXPIRES.** The X32's `/xremote` lasts ~10 s. `ConsoleLink` sends `subscribe()` on connect and then re-sends it from a 1 Hz heartbeat (`kResubscribeMs`); the heartbeat also carries the reply-timeout watchdogs as deadline timestamps, so one timer serves both. Sending it once meant the entire pushed read tier -- scene recalls dropping markers, live name changes -- went dead ten seconds into every show, silently. The same heartbeat runs while ANY link is up (A&H too) and checks `transport->isConnected()`: a dropped Yamaha SCP / A&H TCP link is reported and disconnected, never shown as up. No auto-reconnect (a TCP connect blocks the message thread for up to 2 s).
- **Capture commands require the protocol handshake.** `CaptureServer` does not deliver anything except Hello until the client proves `kProtocolVersion`; a mismatch sends an error and closes. `CaptureLink`'s connection `shared_ptr` crosses threads only through atomic load/store.
- **Completion is "every distinct thing arrived", not "N replies arrived".** The patch stash decremented a counter per reply; since we subscribe to pushed updates, one unsolicited routing message finished the count with an incomplete stash, flipped the desk to card anyway, and left `exitSoundcheck` refusing to restore -- the desk stranded on card returns. Count distinct keys, and range-check every index that came off the wire.
- Remote security boundaries differ: the Generic OSC/UDP bearer token is plaintext on the network; OS entropy and log redaction do not provide confidentiality. Console dialects intentionally accept names/colours, trim-follow and markers without that token, while forbidding transport/arm/mute. Do not describe them as entirely read-only. Protocol-4 helper authentication preserves the existing controller until replacement authentication succeeds, but serialized candidate handshakes can delay attach/reconnect by roughly 1.7 seconds. See the audit residuals before widening network exposure. The desk macro listener is the one tokenless path to transport: opt-in, pinned to one source address, and only guarded entry points. A source address can be spoofed on a LAN; see the 2026-10-31 ADR before widening it in any way.
- **Text off a socket reaches `juce::JSON::parse` only through `linesocket::parseJson` (`Source/Network/LineSocket.h`).** The parser recurses once per bracket with no limit, on whatever thread called it. `jsonDepthWithin` runs first, and its count only holds if it reads text exactly as the parser does. Anything `juce::JSON::toString` writes passes, whatever bytes a name arrived with, so a strange channel name can't get a status line refused. The parser accepts more than JSON, so when you touch this guard or update JUCE, read `juce_JSON.cpp` and `CharPointer_UTF8` again. *Network fixes* compares the guard with the real parser on generated text and runs hostile lines on a thread with a real worker's stack, and a gate rule refuses `juce::JSON::parse` anywhere else in `Source/Network` or `Source/Capture` (loading a local `File` is the listed exception). The capture handshake also caps a line at 16 KB, because nobody has proved anything yet.
- **OSC packets wait in a bounded backlog, not the message queue (`OscPacketReceiver`).** At most 2048 packets or 4 MB; past that the reader drops and counts (`getOverflowCount`) and reports through `onRefusedPacket`. The message thread takes them one turn (4 ms) at a time and goes to the back of its own queue between turns, so timers, meters and STOP keep running under a flood. `disconnect` clears the backlog. Never go back to one posted message per packet: nothing bounds that and the timers wait behind all of it.
- **A marker asked for over the network goes through `RemoteControl::dropRemoteMarker`,** held to `scenefollow::MarkerBudget` (8 at once, then one a second). Console dialects take markers and scene recalls with no token, and each marker costs a sort, a file rewrite and a session-volume write on the message thread. Keys, the twin link and the EDIT view don't pass through it.
- **Console state belongs to a session, except a desk this run moved.** `ConsoleLink::setSessionDir` is called from the 10 Hz timer and before every console action, so no session-swap path can forget it: gains and any saved patch go, and the new session's `console_state.json` loads. `deskOnCardReturns` is the exception: that stash is the only way back for a desk still on card returns, so it survives a session change and a dropped link.
- **The show patch is on disk before the console moves.** `finishPatchStash` saves it with `deskPatch: soundcheck` and only then writes the card returns; if the save fails, the desk is left alone and the stash is dropped. `exitSoundcheck` saves `deskPatch: stage`. A relaunch therefore knows which way to go. A read in which every block is already on card returns is refused: that is not a show patch. `loadJson` never replaces a complete stash or a capture in memory, and takes a file's stash only when it is complete. With no session open, SOUNDCHECK refuses in `consoleToggleSoundcheck`.
- **A console address is a numeric IPv4 address (`oscwire::normaliseSourceIp`),** in `ConsoleLink::connect` and `requestConsoleChannelNames`. A name is looked up on every UDP send on the message thread and a failed lookup isn't cached. `OscUdpTransport` pins its shared socket to that address (`connectToSocket (socket, onlyFrom)`), so a datagram from anywhere else is counted, logged as ignored, and never parsed. It raises the bar and doesn't prove identity: a source address can be spoofed on a LAN.
- **No read-tier message may change a desk.** Yamaha SCP has no `subscribe`: the verb that was there is its scene recall. *Network fixes* fails if any profile's probe or subscribe looks like a recall or a set.
- **MCU bank moves resend every LED and name.** `timerCallback` takes a `force` flag. Resetting the `last` values can't do it: no value compares unequal to both on and off.
- **`session.report.json` has two writers in daemon mode.** `ReportFileLock` (flock on `session-report.lock` in the per-user capture folder, `Endpoint::openSharedFile`) wraps every read-modify-write as well as `publication`. flock crosses processes, excludes separate opens within one, and is dropped by the kernel if the holder dies. The wait is bounded at 3 s because a stuck holder must not cost the report.
- **Reports carry `passSamples`, `passSeconds` and `passMissedSamples` beside the running totals.** `summaryFromReport` compares pass with pass and falls back to the totals for an older report. Failure flags stay cumulative on purpose: a failure earlier in the session is still worth a warning.
- **A leader with no link can edit the address and code during a take.** Only role and port stay locked. The code isn't kept across a restart, so with a daemon take still rolling these fields are the only way back.
- **`StreamingSocket::waitUntilReady` takes the socket's readLock even for a WRITE check.** Never poll writability on a socket that has a reader thread parked in `waitUntilReady(true, ...)` -- the writer starves on the lock and every send fails. Bound a wedged write by making the write MUTEX timed (so other writers fail fast) and by closing the socket from another thread, which is how the rest of the codebase interrupts a stuck send.

- **A scene recall has one rule, `Source/Audio/SceneFollow.h` (2026-10-31).** Both console paths (`ConsoleLink::onSceneRecalled` and every `OscRemote` dialect) call `RemoteControl::onConsoleScene`; never drop a scene marker anywhere else. Capturing (`isRecording()`, local or daemon): drop a named marker at the capture position, whatever Follow says. Not capturing: NEVER a marker. Follow on (`sceneFollow` in appProps, default OFF): locate to the marker of that name, trimmed and case-insensitive, next ahead of the playhead else the first; no match is a status line and nothing else. A scene with no name goes by "Scene N", the same label a take drops, so a number-only desk still finds its marker. Follow refuses under LOCK, a punch's seek lock, `sessionIoBusy` / session transition, and with no audio loaded. The refusals are `scenefollow::locateRefusal`; a new one goes there. A desk talking to both paths reports one recall twice, so `scenefollow::RecallEchoFilter` counts the same label from the OTHER path inside 250 ms once; a repeat on one path is a real second press and still acts.
- **A locate is `RemoteControl::locate`.** It moves the playhead, clears the EDIT cursor and scrolls EDIT; it never starts or stops the transport. Clearing the cursor matters: PLAY starts from a placed cursor, so a stale one would send the next PLAY away from the song. `RemoteControl::Host` is how a headless rule reaches `sessionIoBusy`, the status line and the EDIT scroll; MainComponent sets it in its constructor and clears it first thing in its destructor.
- **LOCK differs between the two scene paths during a take, on purpose.** `OscRemote::oscMessageReceived` refuses everything under LOCK, so a recall on that path drops no marker. `ConsoleLink` has no such gate, so its recall marks the take as it always did. Neither was changed: opening the OSC gate would weaken a guard, and closing the link would lose a locked show's markers. *Console VSC* pins both.
- **Desk macro listener (`Source/Network/DeskMacro.{h,cpp}`) is a narrow door, and stays one.** It answers one pinned IPv4 source on its own port (`deskMacroPort`, default 9301), filtered on the reader thread before parsing; other sources are counted, never posted. It accepts exactly the eight `/zynforge/macro/*` addresses in `deskmacro::kAddresses`, address-only or one integer; integer 0 is a button release. Never add an arm, mute, patch, session or file command to it, and never widen the pin to a subnet, hostname or wildcard: the ADR's risk acceptance holds only for "one address, guarded entry points only". Transport goes through `performRemoteTransport` (STOP is `StopAll`, the host's STOP button, so the two-tap guard stands; it is deliberately not gated on session-busy, or a metadata save could refuse STOP during a take). Markers go through `dropRemoteMarker`. PAUSE refuses during a take because stopping the player under a punch moves its splice. The debouncer measures from the last SIGHTING, not the last command acted on, so a repeating key can't complete the two-tap STOP alone. The listener never starts by itself: it is off on every launch, like the OSC listener.
- **Stereo pairs from the desk are read once, into a new session.** `ConsoleProfile::canReadStereoLinks` is true only with `dialect.queryStereoLink` (X32/M32, `/config/chlink/N-M`); `ConsoleVscTests` fails on either without the other. `RemoteControl::onConsoleStereoLink` keeps a link only during the name capture, so a link pressed on the desk later can never restructure a session. Pairs go through `MainComponent::setStereoLink`, the same path as a strip's menu. Never invent a width message for another desk: the session keeps its names and the status line says to link by hand.
- **`createSessionFromConsole` prefers a connected console link over the OSC listener path.** It is the only path an X32 can answer on, and the only one that hears stereo links. The Control Surfaces hub's "Create Session from Connected Console" button is how an X32 reaches it.
- **Every console message passes `RemoteControl::logOsc`, formatted by `consolelog::describe` (`Source/Network/ConsoleLog.h`).** The sink stores nothing while debug is off. It scrubs the live token and only then cuts to `kOscLogMaxChars`, so a cut can't keep part of a token. It holds `kOscLogMaxLines` (50,000) in a deque, and the header counts what the cap discarded. The log view shows only the last 500 lines and redraws on `getOscLogRevision`; never join the whole log on a timer. `OscPacketReceiver::getCurrentSource()` gives the sender inside a listener callback, since JUCE's Listener carries none. Bundles and datagrams the parser refuses are logged too (`onRefusedPacket`, thinned to 10 a second, address and type tags only, never argument bytes): a desk that sends something we refuse must not look like a desk that sends nothing.
- **Twin Recorder link (`Source/Network/TwinLink.{h,cpp}`, 2026-10-31).** Opt-in, off by default, Session ▸ Network & Surfaces ▸ Twin Recorder (menu 968). Two copies of the app on two Macs, each with its own interface, disks and session. It covers a computer, drive or interface failure and does NOT cover an app bug: never call it an independent recorder, and keep that warning in the panel. `TwinLink` is headless behind `twin::TwinHost`; `MainComponent` implements the host in `MainComponentTwin.cpp`, and every host call happens on the message thread.
- **Link loss never touches a take.** The worker only posts `Up`/`Down` events; no path turns "link down" into a transport action. `outbox` is cleared when a connection begins, so a `start` or `stop` queued for a dead connection is never delivered later, and reconnecting starts nothing.
- **`stop` has exactly one source: `TwinLink::noteLocalStopAccepted`,** called by `noteTwinStopIfEnded` from the two places a confirmed two-tap STOP lands (`onStopClicked`, `handleRecordPressDuringTake`), and only once `engine.isRecording()` is false. Do NOT hook `stopActiveCaptureAsync`, and do not infer STOP from a falling `isRecording()`: device loss, a failed drive and Stop & Quit all end the leader's take and must leave the follower rolling. That is the failure the follower exists for. A follower's local STOP never reaches the leader. Commands arriving at a leader are counted (`ignoredCommands`) and dropped.
- **The leader's take starts first.** `runRecordPlan` calls `noteLocalTakeStarted` only after the take is running, and that call only queues. A punch (`recordPlanPunches`) is an edit of this Mac's take, so it is not relayed; a link RECORD that would punch on the follower is refused in `runRecordPlan`, because nobody on that Mac chose the cursor.
- **LOCK on the follower refuses both link RECORD and link STOP,** the same rule as every other remote transport (`performRemoteTransport`, `handleRemoteTransport`). A locked follower's take keeps rolling and the leader shows why.
- **A follower ends only the take the link started** (`followerTakeId`). A take started by hand on the follower stays rolling on leader STOP, and the leader is told. A leader restarted mid-show re-links the take the follower kept rolling.
- **The link adds no socket patterns of its own.** One owned thread does all socket work, so `StreamingSocket::waitUntilReady`'s readLock has no second reader to starve. `LineSocket.h` holds the shared framing (`pumpLines`, `writeAll`) and `parseJson`; `CaptureLink` uses the same code.
- **All report work runs on `TwinLink`'s report thread, and never while a take rolls or finalizes** (`serviceReports`). A slow disk must not look like a dead link. Edits go through `MultitrackRecorder::editSessionReport`, which holds the same `publication` lock as every report writer. The final hashed report reads `twin` back from the file, because hashing can outlast the merge, and in daemon mode the merge comes from the other process. A continued take carries `twin` forward. Only the `twin` key survives that way: `editSessionReport` is not a general way to add report fields.
- The pairing code is not persisted (no Keychain helper exists), so the link never re-enables itself after a restart. Role, port and the follower's address persist in appProps as `twinRole`, `twinPort`, `twinPeerAddress`.

### Stereo + view linkage

- A stereo pair is two adjacent physical tracks with `isStereo=true` on the L track. Every view (MIXER, EDIT, PATCH) must collapse the pair into one logical entry.
- Mute / solo / arm / gain / pan / colour / name / edit-group changes mirror across the pair automatically — never half-update.
- **A stereo pair is captured as ONE interleaved 2-channel file** named for the L slot (`Track_NN.wav` with 2 channels); there is **no** `Track_(N+1).wav` for the R half. The pair still spans **two physical channels, collapsed into one logical strip** (L = index N with `isStereo`, R = index N+1) on every surface; only the on-disk file is single. This is the native-stereo model adopted 2026-06-13 (see the ADR in `decisions.md`) — it replaced the old "two mono files + `isStereo` flag" storage. How each layer handles it:
  - **Recorder** (`MultitrackRecorder`): the L `WriterChannel` opens one 2-ch writer (`openWriterAtPath(..., numChannels=2)`, `WriterChannel::numChannels=2`); the R slot gets an EMPTY `WriterChannel`. The drain step for the L writer reads BOTH FIFOs (`fifos[i]` + `fifos[i+1]`), stages them into the shard's `stageL`/`stageR`, and does one `writeFromFloatArrays(..., 2, n)`. Byte/roll/RF64 accounting multiplies by `numChannels`. The audio-thread push path + per-channel FIFOs are unchanged (meters, pre-roll untouched). Pre-roll dumps both channels into the 2-ch writer. **The R FIFO stays single-consumer even across a shard boundary**: the R slot's `WriterChannel` is empty, so whichever shard owns the R index skips it (`if (w.writer == nullptr) continue;`) and never drains its FIFO — only the L's drain (one thread) reads both FIFOs. So an odd-indexed pair split across two shards is still race-free; pairs do **not** need to be shard-aligned.
  - **Player** (`SessionPlayer`): `loadSession` sniffs `reader->numChannels`; a 2-ch file expands into TWO `Track`s sharing ONE `PlaybackReader` — the L track reads file channel 0, the R channel 1 (`useRight`). One output stream per physical channel, so index→output is identical to the legacy layout.
  - **Offline render / bounce** (`AudioEngineClips.cpp::ArrangementSource`): `open()` resolves the channel — a 2-ch own-file → read ch 0 (L); no own-file but the prior slot's `Track_<track>` is 2-ch → read ch 1 (R). `bounceStereoPairToWav` thus pulls both halves from the one file.
  - **EDIT waveform** (`EditPage.cpp` `TrackRow`): when the pair is one file (`stereoOneFile`), the L lane draws file channel 0 and the R lane channel 1 from the same thumbnail (`drawLaneL`/`drawLaneR` → `drawChannel`), instead of two separate mono thumbnails.
  - **Import** (`MainComponentSessionIO.cpp`): a stereo source is written as ONE interleaved 2-ch `Track_NN.wav` (`writeStereo`), matching native capture; it spreads pan hard-L/R and **persists `session_mix.json` immediately**.
  - **Legacy compatibility**: sessions recorded the OLD way (two mono `Track_NN.wav` + `Track_(N+1).wav`) keep working everywhere — the player loads two mono tracks, `ArrangementSource` reads each own-file at ch 0, EDIT draws two mono thumbnails. The channel-sniffing makes both layouts transparent.
  - Other collapse points unchanged: **Meterbridge** skips the R half + gives the L meter a `setStereoPartner`; the **Export Audio** dialog shows one "(stereo)" row per logical strip and maps it back via `bounceStereoPairToWav`; `TrackExporter::exportStereoPair` still handles raw per-track stereo export with SR conversion.

### Session-scoped UI state

Some `MainComponent` state belongs to the SESSION, not the app, and every path that swaps the session out must reset it or it silently misfires against the new one. The live examples: `selectedLogical` and `EditPage::activeRowTrackIndex` (`syncStripSelectionScope` and `EditPage::refresh` clear them), `punchEnabled` (`clearSessionState` ends PUNCH mode) and everything `forgetSessionUiState` holds. Grep every assignment when adding another session-swap path.

### Persistence

- Anything the user can edit (track names, colours, routing, gains, stereo pairs, takes, cues, edit-group assignments, markers) must round-trip through one of the per-session files. RAM-only state is a data-loss bug.
- Per-session files live under the session folder:
  - **`session_mix.json`** — the engine writes the full per-strip mix state (name, colour, gain, pan, mute, solo, monitor, arm, routing, output mute, stream send, stereo, edit group, capture gain reference, `referenceMedia`) plus session-level chase start and stream output. Loaded on Open; its `trackCount` is exact, so the recorder grows or shrinks. A missing, malformed, or invalid file returns false and the open funnel sizes from loaded audio, and zero strips over a session that has audio counts as invalid.
  - **`markers.json`** — markers auto-save on add / drop / rename / move; loaded via `markers.setContext(dir, sr)`.
  - **`<Name>.zfproj`** — `setlist` (cues: name, position and each strip's snapshot by UUID), `playlists` (Takes; each clip carries `fadeCurve`, `sourceChannel` and a session-relative `sessionAudioFile`; legacy `audioFile` basenames are resolved against `Audio Files/`), `mediaLengths`, `ui` (view / strip width / zoom).
- Interactive `Save`, cue edits, auto-save and STOP capture immutable serialized metadata on the message thread and enqueue it on the owned `SessionMetadataWriter`. Project read/merge/write and backup copies run on that worker; it must never dereference engine/UI state. Explicit saves retain ordered completion obligations; unstarted layout-only writes coalesce with bounded storage and do not persist unrelated mixer/cue edits. Success requires all requested writes and backup copies; compare current serialized content before marking clean, including edits outside the UndoManager. `saveSessionStateTo` remains synchronous for legacy transactional callers and refuses overlap with pending interactive saves.
- **Auto-save** (`MainComponent::serviceAutosave`, driven from the 10 Hz timer) enqueues a full immutable snapshot on every user-set interval (appProps `autosaveMinutes`, 0 = off, default 5; picker is Session ▸ Auto-Save & Backup…); `writeSnapshot` then skips the backup when nothing changed, ignoring the project's `updatedAt`, so retention counts real changes. It pauses during a take: nothing goes to the take's volume. Do **not** gate it on undo count: recording, routing, cue recall and imports deliberately bypass that counter. The backup itself is `zynforge::sessionbackup::writeSnapshot` (`Source/Audio/SessionBackup.h`, headless-tested): a **full backup session** — a timestamped `Session File Backups/<Name>_<stamp>/` folder copying the session-defining files (`.zfproj`, `session_mix.json`, `session_settings.json`, `markers.json`), **never the audio**, pruned to 10. Save the live metadata first, then snapshot it; advance the clean/last-attempt baseline only if both succeed. On failure, warn and retry after 15 seconds, doubling up to the interval, and name a missing folder. An unloaded session is skipped with a status line and no retry. These are metadata backups; audio is written separately, and restoring old metadata cannot undo a committed punch. Independent media backup/recovery remains necessary.
- Local async STOP uses `AudioEngine::stopRecordingAsync`: capture publication changes once, then the engine owns drain/close/splice/report and reader preparation, the message thread installs prepared state, and owned work retires old readers before completion. Preserve its finalization lease across deferred device callbacks. Main holds the same operation pending through metadata; do not infer idle or allow structural mutation from recording=false alone.
- During async STOP metadata finalization, keep capture/session mutations guarded while servicing UI navigation. Remote STOP retains its first-tap confirmation, then returns false with `finalization pending`; retry after completion returns true only for a successful finalization, while a failed result stays latched. Do not infer finalization success solely from `!isRecording()`. Save & Continue / Save & Close / Save & Quit reserve edits and execute their continuation only after successful, still-current persistence. Destruction drains owned persistence work and retires queued UI callbacks using `SafePointer`.
- Snapshot retention orders by timestamp plus numeric monotonically increasing collision sequence, including legacy `(N)` folders and backward wall-clock jumps. Refuse nonpositive retention before touching files, never follow/prune linked snapshot roots/candidates, and preserve unrelated journals. Retention keeps the newest snapshot with strips when empty mixes would otherwise fill the window. The inherited October 5 patch is covered by all three full 563-group follow-up suites; normal startup was observed, while interactive and physical acceptance remain pending; see the audit report for actual evidence.
- `.zfproj` carries a `formatVersion` field. Treat its absence as v1 and fall back gracefully.
- Per-strip state used to live in **global** `appProps` keyed by index, which leaked between sessions. New sessions / freshly-grown strips now wipe the per-index `appProps` overrides (see `clearStripOverridesRange`); the session files are authoritative.
- Bulk strip reset/range clear batches each StripNames/StripColours/StripGains/StripRouting domain: replace its shared-file cache once, remove all covered keys, then save once; appProps has its own replacement/write. Preserve sibling updates/deletions and unknown keys. The deterministic `Settings batch reset audit` counts reloads and checks persisted/in-memory semantics; S4 targeted Release passes all four groups, with reset/range/growth reloads 5/5/10; all three full follow-up suites also pass. `resetForNewSession` separately batches 27-track defaults to five settings transactions, covered by Review capture repairs.
- **Five `PropertiesFile` instances share ONE `.settings` file** (`appProps` + `StripColours`/`StripNames`/`StripGains`/`StripRouting`), and a whole-file save rewrites every in-memory key. So before mutating+saving, each writer **reloads to REPLACE, not merge** (`clear()` + `reload()`, guarded on the file existing — `StripGains.cpp::reloadReplace`, `AudioEngine::reloadAppPropsBeforeWrite`). A plain `reload()` *merges*: it never drops a key another writer just deleted, so the deleting module's next save resurrects it — this is what made a cleared pan/gain come back on the next `setStripCount` (the "clear didn't stick" bug, locked by the `clearAllStripOverrides` test). Never use a bare `reload()` on one of these shared files before a save. **Corollary for tests + callers:** a `setValue()` that isn't followed by `saveIfNeeded()` is thrown away by the next `reloadAppPropsBeforeWrite()`, because reload-to-REPLACE clears the in-memory copy first.
- **`removeStripAt` must shift EVERY per-index key, not just the Strip\* module ones.** The persistent stores key by array position, so deleting a strip from the middle has to pull `name/colour/gain/pan/in/out` **and** the appProps-owned `strip_stereo_N` + `strip_uid_N` down a slot, then clear the orphan tail. Missing the last two re-formed stereo pairs on the wrong strips and re-stamped the stable IDs on the next `applyPersistedStripState()` — which breaks every cue snapshot, since cues reference strips by `stripId` precisely so they survive a reorder. Locked by *removeStripAt shifts stereo flags and strip UUIDs*.

### Stable identity

- Cue strip snapshots use `TrackState::stripId` (a `juce::Uuid`), so they survive a reorder.

### Dialogs + prompts

- Every prompt that has a text or number field calls `dialog::primeNameEditor(aw, "fieldId")` after the buttons are added: it grabs focus, selects all text, and wires Enter in the field to `exitModalState(1)`. Every AlertWindow prompt in this app uses result code **1** for OK / Apply / Save / Create — don't break that convention.
- A test that needs to answer a delete prompt sets `MainComponent::confirmForTests`.
- For custom `juce::Component` dialogs (`AddTracksDialog`, `NewSessionDialog`), do the equivalent by hand: `setSelectAllWhenFocused(true)` + `grabKeyboardFocus()` (deferred via `MessageManager::callAsync`) + `onReturnKey = [this]{ commit(); }`.
- **Never capture raw `this` in an async menu / modal callback.** `showMenuAsync` and `enterModalState` both OUTLIVE the click that opened them, and a floating dialog can be closed while one is up — use `juce::Component::SafePointer<T> safeSelf (this)` and re-check it inside EVERY nesting level, including the inner modal (`MarkerListDialog` was one that didn't).
- **A FLOATING (non-modal) dialog must re-derive its own enablement from live engine state**, not from what was true when it opened. `AudioDeviceDialog` can be sitting open when RECORD is pressed, so it watches `engine.isRecording()` on a 4 Hz change-gated timer, greys its four device combos, and refuses every mutating path (including the Cancel/destructor revert, which also restarts the device). Static enablement computed in the constructor goes stale the moment the show starts.
- **A dialog control must do what it looks like it does.** Session Info is a read-only summary: the folder name is what the title bar, status line, recent list and `.zfproj` use, and renaming is Save As. A field that appears to rename and doesn't is worse than no field.
- **Export defaults to the SESSION's sample rate, not 48 kHz.** `TrackExporter` has a deliberate bit-exact path when source and destination rates match; hardcoding 48 kHz sent every 44.1 / 88.2 / 96 kHz session down the resampler by default. `ExportDialog::launch` takes the rate, preselects it (adding it to the list if non-standard) and states whether a conversion will happen.
- **`compactPath` only substitutes `~` when the path is actually under the home directory.** An external record drive is `/Volumes/...`; labelling it `~/Volumes/...` on the control that tells the engineer where the take lands is a trust-destroying lie for zero pixels saved.

### Session folder layout

```
~/Music/Zynforge Sessions/<Name>/
├── Audio Files/                  Track_01.wav … (recordings)
├── Export Files/                 stereo mix + per-track exports (was 'Bounced Files/')
├── Session File Backups/         timestamped backup-session folders <Name>_<stamp>/ (session-defining files, no audio; keep 10 newest)
│   └── Before Feature Removal/   original documents of a session from an earlier build that held removed features (see above)
├── <Name>.zfproj                 cues, playlists, UI layout
├── session_mix.json              per-strip mix
├── markers.json                  per-session markers
```
