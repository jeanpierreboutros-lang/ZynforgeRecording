# Changelog

All notable user-facing changes to ZynForge Recording are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning targets [Semantic Versioning](https://semver.org/spec/v2.0.0.html), though the project is pre-1.0 and minor / patch boundaries are pragmatic.

## How this file is maintained

- Add new entries under `## [Unreleased]` as you ship changes.
- When cutting a release, rename the section to `## [X.Y.Z] – YYYY-MM-DD` and start a fresh `## [Unreleased]`.
- Use the categories below. If none apply, the entry probably isn't user-visible and doesn't belong here.
- Keep entries terse but specific. Link to commits or `decisions.md` ADRs when context matters.

**Categories:** `Added` · `Changed` · `Fixed` · `Removed` · `Deprecated` · `Security`.

## [Unreleased]

### Added (latest)
- **EDIT: resize all track rows at once** — track-height changes were per-row only. Now you can size every lane together two ways: **Option-drag** any row's bottom edge and all rows follow to that height live, or right-click a row and pick **Set all tracks to ▸** (micro … extreme / fit to window) to snap every lane to a preset. Single-row resize (plain drag / the normal size list) is unchanged.
- **Tab walks the input list when renaming inline in MIXER + EDIT too** — renaming a channel directly on its strip (MIXER) or row header (EDIT) by double-clicking the name now responds to **Tab** / **Shift+Tab**: it commits the current name and opens the next / previous channel's name editor (wrapping at the ends), scrolling that channel into view first. Same keyboard-only flow as the Rename Channels dialog — type, Tab, type, Tab — now from any of the three places you can rename. (Shared `RenameLabel`.)
- **Rename Channels: Tab walks down the input list** — in the Rename Channels dialog (Track ▸ Batch Rename Channels…), after typing a name you can press **Tab** to jump straight to the next channel's field (and **Shift+Tab** for the previous one), wrapping at the ends. The list scrolls to keep the focused field in view, and the dialog now opens with the first field focused — so you can rename a whole input list keyboard-only: type, Tab, type, Tab.
- **Welcome ▸ New Session picks the record-from input + monitor output device** — the New-session pane of the boot Welcome dialog now has two extra dropdowns, **Input Device (record from)** and **Output Device (monitor)**, populated from the current audio device type and pre-selected to whatever the engine is using. Pick them when you create the session and the choice is applied to the hardware immediately (alongside the sample rate), so the very first take captures from the device you intended and monitoring goes to the right output — no detour through Audio Settings. Leaving them at the current device is a no-op.

### Changed (security)
- **Companion server: secure remote access via tunnels, documented (no in-app TLS)** — the companion stays **loopback-only + token** (secure on the machine), and rather than shipping a self-signed-cert HTTPS stack (browser warnings, extra attack surface), secure phone/off-machine access is now done by fronting `127.0.0.1:9000` with a **tunnel** — Tailscale `serve`, Cloudflare Tunnel, or `ssh -L` — which provides real CA-backed TLS for free. README gained a "Companion server — Security & secure remote access" section with copy-paste recipes; the in-app start message points to it, and the host warns if the server is ever exposed on the LAN in plaintext. See `decisions.md`.

Horizontal scrolling still works via trackpad/wheel.

The yellow clip-start "cut-flag" is gone — a clip's border now shows where it begins. Lane area not covered by a clip is masked to the lane background, so trimmed/split clips read as separate blocks. (`EditPage.cpp`.)

### Added (latest)
- **Long WAV takes are one continuous RF64 file (no more multi-part splits) + crash-safe headers** — a WAV recording that crosses the 4 GiB RIFF limit is now written as a single **RF64** file (one `Track_01.wav`) instead of being split into `Track_01_part02.wav`, `_part03`, … that you had to re-import and consolidate. JUCE writes a normal RIFF file under 4 GiB and promotes the header to RF64 above it; every modern DAW (Pro Tools, Logic, Reaper, Nuendo) reads RF64. To keep one big file safe, the recorder now **rewrites each open file's header every ~5 seconds** while recording, so if the app or machine dies mid-take the file is still readable up to the last flush (header valid, not zero-length) — a crash-safety improvement for AIFF/FLAC too. AIFF and FLAC still auto-split (no RF64 there). See `decisions.md` *RF64 for WAV via JUCE + periodic header flush*.
- **Delete a channel from the EDIT view** — channel removal used to live only under Track ▸ Delete Selected Strips (after clicking the row's narrow name area), and the EDIT Delete key only ever removed clips/ranges, so there was no obvious way to drop a channel while editing. Now: **right-click a track header ▸ Delete Channel**, or select a channel header and press **Delete/Backspace** when no clip or range is targeted. Both confirm first ("Delete channel?"); the recorded files stay on disk — only the channel is removed from the session.
- **EDIT view — Pro Tools-parity edit pass:**
  - **Strip Silence** (Edit menu) — separates each target track's take into clips around the silent gaps and drops the dead air. Opens a **settings box with draggable sliders** (Strip threshold dB, Min strip/silence ms, Min clip length ms, Clip start/end pad ms) before applying. Non-destructive, undoable.
  - **Heal Separation** (Cmd+H) — rejoins a clean split at the playhead, or every healable boundary in the selection (only merges clips genuinely contiguous in the same file).
  - **Consolidate** (Edit menu, and per-clip in the right-click menu) — flattens a range / clip into one new flat file (bakes in gains + fades + clip order).
  - **Clip gain — Pro Tools-style corner fader** — every clip has a gain handle in its bottom-left corner (fader track + triangular thumb + a dB readout on a dark pill). Drag it to ride the level (relative, −60..+12 dB); **Alt/Option-click resets to 0 dB**. The drawn **waveform scales with the gain** (boost = taller, cut = shorter, live while dragging), and playback follows.
  - **Zoom to Selection** (E) — fit the selected range to the EDIT viewport.
  - **Numeric selection readout** — the ruler shows `Sel <start> ▸ <end> (<length>)` in M:SS.mmm when a range is selected.
  - **Clip right-click menu** gained **Rename clip…** and **Consolidate clip** (on top of the existing mute/lock/duplicate/delete/gain/fades).
- **Cmd+Z now undoes mixer moves too** — Undo previously only covered clip + automation edits, so the everyday operations (fader, pan, mute, solo, **rename, recolour**, routing) couldn't be undone and the Undo menu stayed greyed. A coalesced poll now snapshots the mixer and records a single undo step once a change settles (~300 ms — a fader drag is one step, not one per pixel). **Recording is deliberately not undoable** — a captured take can't be undone away.
- **Delete asks before removing a recording** — pressing Delete on a clip/range in EDIT now pops a confirmation ("Delete recording?"). The recorded file stays on disk; Delete only pulls the clip from the arrangement, and Cmd+Z restores it. Shift+Delete (ripple) confirms too.

The view now distinguishes "fresh take, never edited" from "arrangement emptied by the engineer" and draws an empty lane in the latter case (both the waveform lane and the faint substrate behind automation lanes). Non-destructive (the file is untouched; Alt-click the gain resets it), capped by the +12 dB clip-gain ceiling. Great for bringing a quiet DI/take up in virtual soundcheck.

### Fixed (ui)

The Selector now **selects the track you drag on** (Shift-drag to add more), the range shading **only highlights the selected track(s)**, and range edits (Delete / Crop) apply to them. A global loop set via `,` / `.` with nothing selected still spans all tracks (for loop playback).

### Added (session)
- **File ▸ Close Session** — close the current session back to the Welcome screen **without quitting the app**, so you can start or open another session between sets instead of force-quitting and relaunching. Confirms first (recorded audio is always on disk; only unsaved mixer/edit/cue/automation changes are lost), then resets every session-scoped bit of state (audio, clips, markers, automation, cues, mixer strips, undo) to the clean slate and shows the New / Open welcome.

### Fixed (persistence)
- **Per-strip layout no longer leaks across sessions; `session_mix.json` is versioned** — `isBus`, **VCA group**, and **edit group** were still stored in *global* `appProps` keyed by index, so opening a different session inherited the previous one's bus/grouping layout (the same bug class the aux sends had — and the VCA/edit-group copies also went *stale* after a strip reorder, since `swapTracks` never swapped them). All three are now authoritative in `session_mix.json` only; the engine no longer reads or writes them to `appProps`. `session_mix.json` gained a `formatVersion` field (v1) for forward-compatible schema evolution, and the loader is hardened against corrupt/truncated files (unparseable → ignored, absurd `trackCount` → clamped, out-of-range strip index → skipped — all covered by a new test). The session-state round-trip test now covers `isBus` + aux sends + VCA/edit groups, and a new regression test guards the device-restart path (prepare→release→prepare must preserve the track set — the device-change crash class). Also fixed a flaky report test (SHA-256 hashing is now async, so the test waits for it) and a timing-flaky auto-split test.
- **`session.report.json` is now written instantly on stop, every time** — the integrity manifest used to be written *only* on a background thread after hashing every recorded file (GBs), so a large take could finish with no report at all. Now a complete metadata report (track counts, sample totals, missed samples, file lists) is written **synchronously the moment recording stops** with `"sha256Pending": true`; a **background-QoS** thread then hashes the audio and rewrites the report with the sha256 sums (flipping `sha256Pending` to false). The hash pass no longer pegs multiple cores at foreground priority after a big take, and if the app is killed mid-hash the metadata report still stands.
- **Idle CPU drops dramatically at rest** — every channel strip ran a 1024-pt FFT + repaint at 24 Hz forever (even on silence) for its mini-spectrum, which kept the app at tens of % CPU at rest. The spectrum now skips the FFT and goes fully idle once a strip's signal falls below ~−70 dBFS, fading the bars out first; it resumes instantly when signal returns. In addition, when the transport is **stopped** (not recording/playing) and a strip isn't armed/monitored, its LED meter + spectrum **throttle from 30/24 Hz to ~8 Hz** — the meters still move so you can see signal, at a fraction of the cost across 32 strips; they snap back to full rate on record/play/arm. Per-strip dB/clip labels also stop re-laying-out 10×/s unless the value changed. Net: silent idle ~45% → ~0.3%; 32 live inputs at rest ~50% → ~30%.

### Added (latest)
- **Live recording readout — audio load · buffer · disk, prominent while recording** — the header performance dashboard now shows the device **sample rate + actual buffer size in samples** (the real glitch-headroom number), labels the load row **AUDIO** to make clear it's the true CoreAudio callback load (the dropout predictor, not whole-app CPU), and grows larger with a record-red border while a take is rolling so CPU/buffer/disk/DROP are readable at a glance on a dark stage.

### Fixed (more)
- **Changing the audio device no longer crashes the app** — switching input/output device, sample rate, or buffer size called `MultitrackRecorder::release()` on the audio-stop, which `tracks.clear()`'d every `TrackState`. But each ChannelStrip / LedMeter / MiniSpectrum / EditPage row caches a `TrackState&` and the CoreAudio I/O callback reads `getTrack(i)` every block, so the in-flight callback dereferenced freed memory → `EXC_BAD_ACCESS` (use-after-free). `release()` now keeps the per-strip state and only tears down the device/thread-bound writer shards; `prepare()` rebuilds the rate-dependent buffers on the next start — so the channel set survives a device change unchanged (which is what "preserve count across device restarts" always intended). Also hardened the master / click / companion output writes against a device that reports **zero output channels** (`jlimit(0, -1, …)` returned `-1`, a second latent `getWritePointer(-1)` segfault).
- **Keyboard shortcuts now fire reliably** — Cmd+Z (undo), Cmd+Shift+Z / Cmd+R (redo), Cmd+X/C/V (cut/copy/paste) and Cmd+E (separate) were matched on the *text character* under Cmd, which is unreliable on macOS — Cmd+Z silently did nothing while the Edit-menu Undo worked. They're now matched on the physical **key code**, undo/redo handled early so a focused combo can't shadow them, skipped while a text editor has focus. (JUCE doesn't wire native accelerators for non-command menu items, so the menu's "⌘Z" hint is display-only — the keyboard handler is the real path.)
- **Delete-confirmation "Delete" button now actually deletes** — JUCE gives the first of two AlertWindow buttons command-id 1 (not 0), so the confirm callback was reading the wrong button and dropping the action. (Same latent inversion fixed in *Remove Last Capture*.)
- **Export tracks no longer fails with "Export failed"** — both *Export All Tracks* and *Export Individual Track* searched the session **root** for `Track_*.wav`, but recordings live in the `Audio Files/` subfolder — so they found nothing and reported failure. Export now reads from `Audio Files/` (with a legacy root fallback).
- **Menus no longer freeze greyed-out ("nothing works since day 1")** — the macOS menu bar caches each item's enabled/greyed state until the app asks for a refresh, and we never did. So Undo/Redo, the whole Edit menu, Track (cut/copy/paste/solo), and Export stayed frozen in the **empty launch state** (no session, no undo history, no selection) even after you loaded a session, made edits, or selected strips. The app now re-checks the menu-affecting state ~10×/s and refreshes the menu when it changes, so items light up the moment they're usable.
- **Empty app on launch** — see "Fixed: empty-app-on-launch" — the app now reopens the last session and sizes the mixer from the recorded audio, so the menus that need tracks/a loaded player are actually reachable.
- **Aux send routing no longer leaks between sessions** — sends were stored in *global* app properties keyed by strip index, so opening a different session inherited the previous session's send routing (and they never round-tripped through the authoritative `session_mix.json`). Sends are now saved/loaded per-session in `session_mix.json`; `setTrackSend` no longer writes global appProps and the loader no longer reads them. (Old sessions just start with no sends until re-saved.)
- **EDIT audit pass — three "looks done but wasn't" bugs:**
  - **Markers lane now shows real markers** — it used to paint 6 fake evenly-spaced ticks + the literal word "markers", ignoring the session marker list. Now maps each real marker to its true timeline position with its name.
  - **Clip waveforms follow the clip** — the lane drew one continuous full-width thumbnail, so after a clip Move or slip-trim the block moved but the waveform under it stayed (wrong audio). Each clip block now draws its own waveform, mapped to the clip's file region.
  - **Snap now affects dragging** — the "Toggle Snap" toggle only snapped split-at-playhead; dragging a clip ignored it. A Move drag now snaps the clip start to the grid/nearest marker.
- **EDIT playhead + edit cursor no longer show as two confusing bars** — Pro Tools-style: while the transport is stopped the green playhead and white insertion point are the same line (a click moves both); the separate white edit cursor only appears while playing, where it marks the edit point as the playhead rolls away.
- **Delete now reliably clears a selected range in EDIT** — switching views (and entering EDIT) pulls keyboard focus back to the app, so Delete / the tool keys are no longer swallowed when focus was left on a now-hidden MIX control. Selecting a range with the Range tool and pressing Delete clears the audio inside it across the target tracks (Shift+Delete ripple-deletes).

### Added (latest)
- **Edits now render to the deliverable (P0 -- bounce + mixdown)** — the EDIT view was audition-only: export copied the raw `Track_NN.wav` and ignored every clip edit. Now **File ▸ Export ▸ Bounce Edited Tracks (Stems)** renders each track's clip arrangement (positions, fades incl. equal-power, clip gain, mutes, active take) to flat 24-bit WAVs, and **Bounce Stereo Mix** sums the whole edited arrangement through gain/pan/mute/solo + volume/pan/mute automation + VCA + master to a 24-bit stereo WAV. Offline on a worker thread (no real-time risk). Engine `renderTrackArrangement` + `renderStereoMix`, both unit-tested.
- **Cross-track clip paste (P2-7)** — copy a clip and paste it onto a *different* track; it plays the copied audio there. `SessionPlayer` gained a file-keyed reader cache, strictly additive (clips with no `audioFile` are byte-identical to before); the paste references the source track's file, round-trips in the `.zfproj`, and the bounce honours it.
- **Take comping (P1-5)** — build one keeper from the best section of each take: select a range, then the take menu's **Comp selection from ▸ Take N** splices that take's audio for the range into the active comp. Engine `compRangeFromTake`, clip-undoable.
- **Edit groups propagate clip edits (P1-3)** — Separate/Clear/Ripple/Split and drag move/trim/fade stay phase-coherent across an EDIT group; clicking a grouped clip selects its peers.
- **Master loudness: BS.1770 LUFS + true-peak (P2-6)** — momentary/short-term/integrated (gated) LUFS + 4x-oversampled true-peak on the post-fader master, shown on the BigClock panel.
- **Equal-power crossfades + timeline minimap (P2-8)** — per-clip fade curve (linear/equal-power) and a draggable overview navigator strip when zoomed.
- **EDIT view round 2: multi-clip selection, ripple delete, audio clip clipboard, configurable nudge** — building the region editor toward a full DAW:
  - **Multi-clip selection** — Shift+click adds clips to the selection (across tracks); Delete / Nudge act on the whole set at once. Each selected clip shows the teal highlight.
  - **Ripple delete (Shift+Delete)** — deletes the selected clip or range **and closes the gap** (later audio slides earlier), vs plain Delete which leaves a gap. New engine `rippleDeleteRange`.
  - **Audio clip clipboard (Cmd+X / Cmd+C / Cmd+V)** — cut/copy the selected clip and paste a copy **at the playhead** on its track; new engine `pasteClip`. (Same-track for now — clips index into their track's file; cross-track paste needs per-clip readers, a later refactor.) When no clip is selected, Cmd+X/C/V keep their old strip-settings behaviour.
  - **Configurable nudge** — **N** cycles the nudge step (10 / 25 / 50 / 100 / 250 / 500 / 1000 ms, persisted); **Alt+Left/Right** or **numpad +/-** nudge the selected clip(s) by it. With nothing selected, numpad +/- nudges the playhead.
  - All clip-aware-undoable. Regression test (`rippleDeleteRange` closes the gap, `pasteClip` inserts a clip), 134 test groups.
- **Clip selection + Delete / Duplicate / Nudge in the EDIT view** — click a clip (with the Smart or Move tool) to select it; it highlights with a teal wash + border so you see exactly what an edit will hit. Then **Delete** removes it, **D** duplicates it after itself, and **Alt+Left/Right** nudge it 100 ms earlier/later. All clip-aware-undoable. Clicking empty lane space clears the selection; structural edits (split / separate / clear) clear it too so the highlight never goes stale.
- **EDIT tools are now a real DAW edit workflow (Separate / Clear), not just a tool picker** — the six edit tools (Smart / Range / Trim / Move / Fade / Scrub) looked like Pro Tools but the Range selection led nowhere. Now:
  - Each tool shows a **readable caption under its icon** and a plain-language tooltip explaining exactly what it does on a click/drag (no more guessing from a cryptic glyph).
  - **Split (`S`) acts on every track by default** instead of doing nothing unless you'd first selected strips.
  - **Separate (`B`)** isolates the selected range as its own clip across every track (or just the selected strips) — the core Pro Tools "B" gesture, built on a new `splitTrackAtSample`.
  - **Clear (`Delete`)** removes the audio inside the selected range across tracks, leaving a gap — non-destructive (the WAV files are untouched) and Cmd+Z restores it. Built on a new `clearTrackRange`.
  - All of these are clip-aware-undoable and round-trip through the `.zfproj` playlists. New regression test (`splitTrackAtSample + clearTrackRange`, 133 test groups).
- **Live capture waveform while recording** — the EDIT lanes used to stay blank during a take (the file thumbnails are only re-scanned from disk after STOP, to protect capture integrity), so there was no on-screen confirmation a track was actually recording until you stopped. Each armed lane now draws a **red capture envelope that grows left→right in real time**, built from the live input meter (`TrackState::peak`) — no disk reads, so capture integrity is untouched. The EDIT time ruler turns its playhead red and shows the elapsed-record time, growing to fit the take. On STOP the real full-resolution file waveform replaces the live envelope as before. Confirmation at a glance that signal is hitting each channel during the take.

### Fixed (latest)
- **Recording a second take no longer wipes earlier takes' tracks (data loss)** — recording one channel, then arming a *different* channel and recording again into the same session, silently deleted the first channel's audio. `startRecording` opened a fresh writer for **every** non-bus track regardless of arm state, and opening a writer truncates the target file — so the still-unarmed earlier track's `Track_NN.wav` was wiped to an empty file. Writers are now opened **only for armed tracks**; unarmed tracks keep their existing files untouched, so takes accumulate in the session instead of overwriting each other. Regression test added (132 test groups).
- **Removed the amber transient-onset ticks on the EDIT lane** — the small orange tick marks (Tab-to-Transient hints) on the active row read as visual clutter. Tab / Shift+Tab still jump between transients; the markers just aren't painted anymore.

### Changed (latest)
- **EDIT track rows now have a gap between them** — the lanes used to butt flush against each other, so adjacent tracks ran together visually. Each row is now separated by a small dark (bgDeep) gap, matching the existing "rows = light, empty area = dark" language, so every track reads as its own block.
- **EDIT time ruler rebuilt to read like a pro DAW timeline** — the old ruler was a flat row of faint ticks with a single label every 30 s. It now draws a graduated major/mid/minor tick hierarchy on a 1-2-5 progression (0.1 s → 2 h) that adapts to zoom, with labels that never collide and switch to tenths when zoomed in and to `H:MM:SS` past an hour. No internal caller is affected (crop/split rebuild clips directly rather than going through these). Test extended to assert delete + duplicate are refused while locked and succeed after unlock.
- **Deleting the last clip on a track now silences it (was reverting to whole-file playback)** — the player treated an empty clip list as the lazy "play the whole `Track_NN.wav`" default, which is correct for a track that's never been edited but wrong once you've deleted everything off it: the track would suddenly play its full original file again instead of going quiet. `SessionPlayer` now tracks, per track, whether the engine has *explicitly* set a clip list; an explicit-but-empty list renders silence, while a track the engine never set clips for still falls back to whole-file (so untouched tracks keep playing). Verified by a file-backed player-render test that deletes the last clip and asserts the output is silent.
- **Split did nothing after opening an audio folder (wrong subsystem guard)** — `splitTrackAtPlayhead` bailed out when `track >= recorder.getNumTracks()`, but opening an existing session/audio folder loads the *player* (which holds the tracks + files) without sizing the *recorder* (the capture side), so its count stayed 0 and every split was silently refused even though the audio was right there. The guard now bounds against whichever subsystem knows about tracks (recorder OR player); the existing on-disk `Track_NN.wav` existence check remains the real gate. Verified by a new file-backed end-to-end test (`Clip split + crop`) that records a real take, loads it, and asserts split produces two timeline-adjacent, file-contiguous clips that round-trip through undo. (Recording-then-editing in the same session already worked, since arming sets the recorder count.)
- **Clip edits were silently lost on save/reload and ignored by undo (active-take desync)** — every live clip edit (split / trim / move / fade / gain / mute / lock / delete / duplicate) mutated the live `trackClips` list the player renders, but never mirrored the result into the active Take. Since `.zfproj` persistence and the new clip-aware undo both serialise the *Take* (`playlistsToJson`), the edits never reached disk and undo's before/after snapshots came out identical — so reopening a session dropped all comping work and Cmd+Z was a silent no-op for everything except Crop (the only path that happened to mirror). Root cause: the documented "active take == trackClips" invariant was only upheld by `cropToRange`. Fix: a single `AudioEngine::syncActiveTake(track)` helper now mirrors the live clips into the active take (creating Take 1 if none) and is called at the end of every mutator. New headless regression tests (`Clip edit persistence/undo`) assert that an edit actually changes `playlistsToJson` and round-trips through undo/redo.
- **Recordings no longer corrupt under multi-channel load (writer-thread race)** — the recorder drained its per-channel FIFOs to disk across a *pool* of writer threads. Under real parallelism this corrupted captures: whole channels came back as white-noise garbage, non-deterministically, worse with more channels (this is the "weird form" / glitchy takes). Disk writing is now serialised on a single thread — more than enough for the I/O load (~6.6 MB/s for 48ch/24-bit/48k) — which a new headless integrity test (`RecordingIntegrityTests`, run via `--run-tests`) proves clean across 8/16/48-channel captures (and which reproduced the bug at 2+ threads). See `decisions.md` "Single writer thread for capture".
- **Recordings were truncated / glitched (stop-time data race)** — `stopRecording()` did its final FIFO flush and closed the writers on the message thread *while the shard writer threads were still draining*. That meant two consumers on each single-consumer FIFO and `writers.clear()` freeing an `AudioFormatWriter` mid-`writeFromFloatArrays`, which corrupted samples and truncated files at random per-channel lengths — yet each WAV header kept the full intended sample count (header said 24 s, the data was 8 s), so players read past the real audio into garbage and the takes sounded glitchy / unclear. Fix: detach the shard clients from their writer threads (which blocks until any in-flight drain finishes) **before** the final single-threaded flush + close, then re-attach for the next take. All armed tracks now finalize at the same correct length.
- **Patch page is now scrollable (both axes)** — the INPUT / OUTPUT PATCH grid painted rows/columns at a fixed offset with no way to reach hardware channels past the window bottom or strips past the right edge, so on a high-count interface (e.g. a 64/128-channel Dante card, or many strips) you couldn't see or patch them. Added vertical **and** horizontal scrollbars + mouse-wheel / trackpad scrolling, with frozen panes: the strip-header band stays put while scrolling vertically, and the HW-channel label column stays put while scrolling horizontally, so identity is always visible. Click + drag-patch hit-testing accounts for both scroll offsets; each scrollbar hides when its axis already fits.
- **Crash on quit (static font teardown)** — quitting the app could `terminate()` during `__cxa_finalize`: the BrandTokens font cache (a function-local `static std::unordered_map<size_t, juce::Font>` plus ~14 `static const juce::Font` role accessors) and the LookAndFeel's `static juce::Typeface::Ptr` faces were destroyed *after* JUCE tore down CoreText, so their CoreText typeface destructors fired into a dead framework. Fix: the font cache is now cleared from `JUCEApplication::shutdown()` (while CoreText is alive), the role accessors route through that clearable cache instead of holding their own statics, and the LookAndFeel's bundled typefaces are now members (released when the LookAndFeel dies during shutdown). No behaviour or perf change in normal use — the cache still resolves each (size, weight) once.
